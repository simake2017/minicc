# 07 链接与运行时 —— 自研链接器直出可执行文件

## 定位

| 项 | 内容 |
|---|---|
| 管线位置 | 阶段 6，最后一步（默认路径自动触发；`-S` 只吐汇编则跳过） |
| 输入 → 输出 | 系统 as 产出的 .o（ELF64 可重定位）⇒ 非 PIE 可执行文件 |
| clang 对照 | 无直接对应——lld/ELF 才是同类（本版只支持输入 .o 子集 + 非 PIE） |
| 权威文档 | docs/learn/15 |

## 核心机制与判据

- **不依赖系统 ld / crt / libc**：借系统 `as` 把 .s 汇编成 .o，之后合并节、
  符号决议、重定位回填全部自研。内置 `_start` 入口 + 64KB bump 分配器的
  malloc/free。
- **五步流水线**（与 learn/15 一一对应）：解析 ELF 头与节表 → 合并同类节 →
  符号决议（全局符号跨 .o 对齐地址）→ 重定位回填（R_X86_64_PC32/PLT32/64）→
  写可执行文件头与程序头。
- **非 PIE**：加载地址固定，重定位可按绝对地址直接算，免掉 GOT/PLT 一族复杂度
  ——这是教学取舍，换来"Hello World 从头到尾全是自己的代码"。
- **链接期即验收**：undefined reference 在这是最后防线——CodeGen 符号拼错
  （历史上 B10/B20/B22 全是这类）编译期全绿、唯独这里响亮报错。
