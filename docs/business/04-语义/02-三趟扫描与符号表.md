# 04.2 三趟扫描与符号表 —— 注册时机

> 上级：[00-总览](00-总览.md)。

## 管什么

SemanticAnalyzer::analyze 的三遍走查与 m_symbolTable 的构建/消费时机。

## 关键判据

- **三遍分工**：Pass 1 注册类/模板蓝图/静态成员声明 → Pass 2 注册函数名
  （mangling 在此定型：同名多参追加 `_N`，**有状态**）→ Pass 3 分析函数体
  （inferType 链 + 回填槽）。
- **先使用后声明**靠三遍顺序保证：Pass 3 查表时 Pass 1/2 已全注册完。
- ★ **命名空间遍历是独立原语** forEachFunctionDecl：Pass 2/3 曾扁平遍历漏掉
  命名空间（Sema 全对但 CodeGen 没收到方法 ⇒ undefined reference），
  Pass 1 曾顺手注册导致符号重复——镜像 bug 一对，现统一走递归原语。
- **符号表是决议记录**（值/函数/类型的终态），不是临时工作区；类模板蓝图
  单独走 m_classTemplates 注册表（Pass 1 只打 `↳ class template 'Box' registered`，
  蓝图**不经过** processClassDecl——B18 的坑根）。
- **回填槽哲学**：凡 mangling 有状态的选定（构造函数 ctorSymbol、成员方法
  resolvedCalleeSymbol、下标 atSymbol），都由 Sema 选定并回填 AST 槽，
  CodeGen 优先用回填值——★ CodeGen 不知道重载后缀，硬拼必错（B10）。
