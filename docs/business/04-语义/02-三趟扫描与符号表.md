## §1 管什么（定位）

SemanticAnalyzer::analyze 的三遍走查与 m_symbolTable 的构建/消费时机。

## §2 关键判据（详细设计）

- **三遍分工**：Pass 1 注册类/模板蓝图/静态成员声明 → Pass 2 注册函数名
  （mangling 在此定型：同名多参追加 `_N`，**有状态**）→ Pass 3 分析函数体
  （inferType 链 + 回填槽）。
- **先使用后声明**靠三遍顺序保证：Pass 3 查表时 Pass 1/2 已全注册完。
- ★ **命名空间遍历是独立原语** forEachFunctionDecl：Pass 2/3 曾扁平遍历漏掉
  命名空间（Sema 全对但 CodeGen 没收到方法 ⇒ undefined reference），
  Pass 1 曾顺手注册导致符号重复——镜像 bug 一对，现统一走递归原语。
- **符号表是决议记录**（值/函数/类型的终态），不是临时工作区；类模板蓝图
  单独走 m_classTemplates 注册表（Pass 1 只打 `↳ class template 'Box' registered`，
  蓝图**不经过** processClassDecl——B18 的坑根）。
- **回填槽哲学**：凡 mangling 有状态的选定（构造函数 ctorSymbol、成员方法
  resolvedCalleeSymbol、下标 atSymbol），都由 Sema 选定并回填 AST 槽，
  CodeGen 优先用回填值——★ CodeGen 不知道重载后缀，硬拼必错（B10）。

## §3 诊断类别（异常处理）

本模块的诊断由 `src/sema/semantic_analyzer.cpp` 的唯一出口 `error()` 打出，输出形态
`[Semantic Error] {行:列}: {文案}`。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 同一作用域里变量重名 | `Variable '{名}' already declared in this scope` | 否 |
| 2 | 同一作用域里重复定义 | `redefinition of '{名}'` | 否 |
| 3 | 重复定义且类型不同 | `redefinition of '{名}' with a different type: '{类型1}' vs '{类型2}'` | 否 |
| 4 | 名字在作用域链与全局都查不到 | `Undefined variable '{名}'` | 否 |
| 5 | 语句层裸名 `S;` 可见但不是类型名 | `use of undeclared identifier '{名}'` | 否 |
| 6 | 基类名在类注册表里查不到 | `Base class '{名}' not found` | 否 |
| 7 | static 成员重复声明 | `duplicate static member '{名}'` | 否 |
| 8 | 类型限定访问一个不存在的 static 成员 | `no static member '{名}' in class '{类名}' —— 类型限定访问 Cls<Args>::member 只解析静态成员；若此处是 SFINAE 探测，说明偏特化被移除后回退到的主模板没有该成员（对照 test_tmpl_36 的兜底写法）` | 否 |
| 9 | 全局变量的初始化式类型与声明类型不符 | `Cannot initialize global variable '{名}' of type '{声明类型}' with value of type '{实际类型}'` | 否 |
| 10 | 类外定义的 static 成员与类内声明的类型不同 | `redefinition of '{名}' with a different type: '{类型1}' vs '{类型2}'` | 否 |

★ 第 10 条的判据用 **`equals`（同类型）**而不是 `typeCompatible`——后者会误放行 long vs int
（ODR 要求单定义）。

## §4 Out of Scope（本模块不做的事）

- **命名空间变量在块作用域不可见**：`namespace N { int g; }` 里裸用 `g` 查不到——B37 查实的缺口，本轮未修（ROADMAP 登记）。
- **嵌套类不支持**：`class A { class B { }; };` 的 `A::B` 不可用。
- **符号表不做完整的块作用域链回退**：`lookupVisibleType` 的三跳是「类作用域别名 → 命名空间链逐级外层 → 全局」，变量从内层块回退到外层块**不做**。
- **不做 ODR 探测**：同一个符号在两个 TU 各定义一次，本项目不做跨 TU 检查。
- **类模板蓝图不经过 `processClassDecl`**：蓝图走独立的 `m_classTemplates` 注册表（这正是 B18 的坑根），因此蓝图里的成员**不参与**本模块的注册时机判定。
- **不做两阶段查找的完整分离**：非依赖名的"定义期查表"目前靠名字登记表这半边（见 03-解析/05-名字识别），依赖名的"实例化期再查"在 05 模板域。
- **Pass 1 不做成员注册**：成员模板/成员方法在 Pass 2 注册（mangling 在此定型），Pass 1 只登记类名与模板蓝图。

## §5 观测点（日志键）

本模块的注册时机可观测——Pass 1/2/3 每一步都打 `[register]`：

| 时机 | 打的键 |
|---|---|
| Pass 1：类登记 | `[register] class '{名}'` |
| Pass 1：类的前向声明（只登记名字，不产符号） | `[register] class '{名}' (forward declaration ⇒ 只登记名字，不产符号)` |
| Pass 1：类型别名 | `[register] type alias '{名}' = {目标}` |
| Pass 1：枚举 | `[register] enum '{名}' ({n} items)` |
| Pass 1：模板蓝图 | `[register] template <...>` |
| Pass 1：推导指引 | `[register] deduction guide for '{名}' (#{序号}) registered` |
| Pass 2：全局变量 | `[register] global variable '{名}' : {类型}` |
| Pass 2：函数 | `[register] {名}({形参}) → {返回类型}    [mangled: {符号}]` |
| Pass 2：类模板蓝图登记 | `↳ class template '{名}' registered` |
