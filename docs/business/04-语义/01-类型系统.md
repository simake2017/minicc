## §1 管什么（定位）

编译期类型的**值语义**表示：Type 节点树（Basic/Pointer/LValueRef/Const/Class/
TemplateParam/Array…）。运行期只有宽度（sizeInBytes）和地址。

## §2 关键判据（详细设计）

- **equals 是同一性判据**：类型缓存键、mangling、平凡拷贝判据全吃它。★
  `toString()` **不是单射**（`Const(Pointer(Int))` 与 `Pointer(Const(Int))` 都印成
  `const int*`）——拿给人看的串当机器键，早晚出事（learn/23；实例缓存键已改
  lossless 版，05.2）。
- **cv 位置精确**（learn/23）：`const int*` = Pointer(Const(Int))；
  `int* const` = Const(Pointer(Int))；`const int&` = LRef(Const(Int))。
  ★ cv 位置一改，所有"按旧形态看类型"的地方都要重看一遍（B26 的 const 剥除
  分支就是踩了这个）。
- **可表示性收口** canRepresentValue（B17）：NTTP 实参判据不是"形态精确相等"
  （会拒收 `Flag<1>`、`A<4L>` 合法程序），而是 [temp.arg.nontype]/1 → [expr.const]/10
  → [dcl.init]/7 的**值可表示**；通过后**形态归一**（a.valueType = p.nonType），
  `Buf<4L>` 与 `Buf<4>` 才是同一实例。
- **谓词族**：isInteger/isChar/isUnsignedInteger/integerBitWidth；sizeInBytes
  从位宽**推导**（一处真源，不再两处各写一份）——CodeGen 按宽度分派、零
  TypeKind 引用，新标量类型的代码生成成本为 0。
- **stripReferences/stripConst** 只服务类性/族性判定；标量路径、日志、符号表
  里的原 type 不动（非 const 程序汇编逐字节不变，B34）。

## §3 诊断类别（异常处理）

`src/ast/type.cpp` 本身**不产生诊断**（它是纯类型工厂 + 判据）。类型相关的诊断由
`src/sema/semantic_analyzer.cpp` 在**用到类型判据**的地方打出，输出形态
`[Semantic Error] {行:列}: {文案}`。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 依赖限定者里的成员名不是类型 | `no type named '{名}' in '{类名}'`（src/sema/semantic_analyzer.cpp:329 / 993，经 `Sfinae::fail`） | 否 |
| 2 | 名字从未作为类/类型被声明过 | ``unknown type name '{名}' —— 该名字没有作为类/类型被声明过。（语句层的声明/表达式歧义（`a < b > c;`、裸 `S;`）由语义期的名字可见性判据裁决（docs/learn/48）；能走到这一步的 `名字 标识符/;` 是【真正的】未知类型名。）`` | 否 |
| 3 | 初始化式类型与声明类型不符 | `Type mismatch in '{名}': declared '{声明类型}', got '{实际类型}'` | 否 |
| 4 | `auto*` 推导的初始化式不是指针 | `cannot deduce 'auto*' for '{名}': initializer is '{实际类型}', not a pointer` | 否 |
| 5 | `auto` 完全推不出来 | `Cannot deduce auto type for '{名}'` | 否 |
| 6 | NTTP 实参的值不能表示成形参类型（可表示性判据） | `non-type template argument evaluates to {值}, which cannot be narrowed to type '{形参类型}'` | 否 |
| 7 | 解引用非指针 | `Indirection requires pointer operand ('{类型}' invalid)` | 否 |
| 8 | 对空类型解引用 | `Cannot dereference a null-typed operand` | 否 |
| 9 | 对空类型取地址 | `Cannot take the address of a null-typed operand` | 否 |
| 10 | 对 void 表达式取地址 | `Cannot take the address of a void expression` | 否 |

★ 第 1 条的硬错误文案与 clang++-18 **逐字相同**（`no type named 'type' in 'WithoutType'`）。
★ 第 6 条是 B17 的修法：判据从"形态精确相等"换成**可表示性**——`Flag<1>`（bool←int 1）/
`A<4L>`（int←long 4）/ `A<true>` 这三条 clang 认可的合法程序在旧版全被拒。

## §4 Out of Scope（本模块不做的事）

- **`toString()` 不是单射**：`Const(Pointer(Int))` 与 `Pointer(Const(Int))` 都印成 `const int*`——**机器用的键一律走无损版**（`losslessArgumentsKey` / `renderArgLossless`），不许拿 `toString()` 当键（learn/23 的教训）。
- **不做用户自定义类型转换**：`operator T` 与转换构造函数都没有——可隐式转换只覆盖算术族与指针/引用的标准转换。
- **不做后置 const 的重载区分**：const 成员函数与非 const 同名**不构成重载组**（ROADMAP 登记为待做）。
- **不做 `volatile` / `restrict` / `_Atomic`**：cv 族只做 `const`。
- **`Type` 是树形节点而非 interned 规范形式**：`int*` 与 `int *` 语法同形但节点不同，判等靠 `equals()`，不靠 `toString()`。
- **不做位域（bit-field）与 `alignas`**：数组类型已支持（learn/42），位域未做。

## §5 观测点（日志键）

**本模块不打日志**——src/ast/type.cpp 里零 `std::cout`，类型工厂是纯函数。

★ 类型判据的可观测痕迹在**消费方**（语义域）打出：

| 时机 | 打的键 | 归属 |
|---|---|---|
| 字面量的 (值, 形态) 判定 | `[infer] IntLiteral({值}) → {形态}` / `[infer] CharLiteral({值}) → char` | 04 语义 |
| 二元运算的结果类型 | `[infer] {左} {op} {右} → {结果类型}` | 04 语义 |
