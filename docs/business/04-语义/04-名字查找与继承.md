# 04.4 名字查找与继承 —— 成员查找的三条原语

> 上级：[00-总览](00-总览.md)。

- 读者：改成员查找或继承相关判据的开发者
- 审法：查找判据单点（三个原语）；隐藏按名字、可行性按类型，两者正交
- 名词版本：v1

## §1 管什么（定位）

"成员 m 住在哪个类/哪个子对象"的全部判定。查找原语收口为三个：
findMethodInHierarchy / findField / resolveQualifiedField。

## §2 关键判据（详细设计）

- **同一判据不许写两份**（B10 的共同教训）：inferMember 与 inferCall 共用同一
  查找谓词；B12（继承方法查不到）就是写在两处且不一致的产物。
- **findField 三级**（[class.member.lookup]/3）：全限定名 → **自身字段优先**
  （隐藏）→ 继承。★ 旧版隐藏方向做反，d.x 静默指向 A::x（B14 真 miscompile）。
  多继承同名 ⇒ findFields 歧义诊断（[class.member.lookup]/8，文案逐字同 clang）。
- **隐藏（按名字）与可行性（按类型）正交**（B24/B25）：成员查找 BFS 里"查到
  名字就下结论"——本类为这个名字声明过东西 ⇒ 当场了结（个数区外 too few/too
  many，区内 no matching member），**不往基类走**。两个筛选是正交的，混在一次
  遍历里必然错。
- **resolveQualifiedField**（B21）：`Base::v`（隐式 this）与 `obj.Base::v`
  两形态；★ **核心是回填偏移**——按裸名查会命中派生类隐藏字段那条，程序照跑、
  结果错。
- **ADL 是补进同一候选集，不是兜底**（learn/26）：`measure(s)` 里 N::measure(S)
  与全局 measure(int) 同场竞争，先到先得会静默调错函数。
- **继承的引用绑定等边界未做**：`Base& b = d;` 派生到基类引用（ROADMAP 登记）。

## §3 诊断类别（异常处理）

本模块的诊断由 `src/sema/semantic_analyzer.cpp` 的 `error()` 打出，输出形态
`[Semantic Error] {行:列}: {文案}`。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 类里没有这个成员（字段或方法） | `No member '{名}' in class '{类名}'` | 否 |
| 2 | 限定名访问的成员不存在 | `no member named '{名}' in '{限定名}'` | 否 |
| 3 | 多继承里同名字段在两个基类子对象中都有 | `Member '{名}' is ambiguous in class '{类名}': found in {n} base-class subobjects ({列表})` | 否 |
| 4 | 对非类类型取成员 | `Cannot access member '{名}' on non-class type '{类型}'` | 否 |
| 5 | 对空类型取成员 | `Cannot access member of null type` | 否 |
| 6 | 成员函数调用的实参个数不在候选集内 | `no matching member function for call to '{名}' in class '{类名}' ({n} argument(s) given; 实参类型无法按 [overload.viable] 转换)` | 否 |
| 7 | 成员函数调用的实参个数太少 | `too few arguments to function call, expected {n}, have {m}` / `too few arguments to function call, single argument '{参数名}' was not specified` | 否 |
| 8 | 成员函数调用的实参个数太多 | `too many arguments to function call, expected {n}, have {m}` / `too many arguments to function call, expected single argument '{参数名}', have {m} arguments` | 否 |
| 9 | 名字在作用域链与全局都查不到 | `Undefined variable '{名}'` | 否 |

★ 第 1、3 条与 clang++-18 **逐字相同**。
★ 第 6~8 条的"个数区外"分支与 clang **逐字相同**（B24/B25 的修法：查到名字就下结论，
不往基类走）。

## §4 Out of Scope（本模块不做的事）

- **派生类 → 基类的引用绑定不做**：`Base& b = d;` 未实现（ROADMAP 登记）。
- **`using Base::f;` 把隐藏名字拉回来不做**：该语法未实现。
- **限定名**调用**成员函数**不做：`d.Base::f(2)` 不支持（B21 只管数据成员 `Base::v` / `obj.Base::v`）。
- **ADL 只走关联命名空间**：不做模板实参关联的完整推导（[basic.lookup.argdep]）。
- **`v[i]` 的值类别按 `at()` 返回类型判定**尚未做：现按节点种类判（learn/36 §7 边界表登记）。
- **不做 `virtual` 函数的 `override` 校验**：槽位认领按签名，但"是否真的覆写了基类虚函数"不校验。
- **名字查找不做"隐藏 vs 可见"的完整重载集**：`using` 声明与嵌套作用域重名不参与重载集组建。

## §5 观测点（日志键）

**本模块不打独立日志键**——查找原语（`findMethodInHierarchy` / `findField` /
`resolveQualifiedField`）是纯查询，成功时不打印。

★ 可观测痕迹在命中之后：

| 时机 | 打的键 | 归属 |
|---|---|---|
| 字段命中（带偏移与大小） | `[member] {类}.{字段} → {类型}    (offset={n}, size={n})` | 04 语义 |
| 方法命中（沿基类链） | `[member] {类}.{方法名}() → {返回类型}    (method via '{基类}')` | 04 语义 |
| 限定名命中（回填了偏移） | `[member] {类}.{名}::{成员} → {类型}    (qualified member, offset={n})` | 04 语义 |
