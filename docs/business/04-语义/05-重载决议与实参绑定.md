## §1 管什么（定位）

调用点从候选集到唯一函数的裁决：自由函数、成员方法、构造函数、下标糖四路
共用一套判据。

## §2 关键判据（详细设计）

- **择优原语单点** pickBestByArgs：精确匹配 → 可隐式转换 → **无可行候选报
  错**（B27 删掉"退回声明序首个"——它把"判不了"（依赖上下文，argTypes 含
  nullptr）与"判出来没人行"混成一件事，是静默算错）。保留两个例外：argTypes
  含 nullptr ⇒ 取首个（SFINAE 探针场景）；单候选不打日志（零漂移策略）。
- **绑定可行性先于择优**（B26）：谓词 argsBindTo 与报错 checkArgBinding **分开**——
  绑定是 [overload.viable] 的一部分，必须在择优之前剔候选，否则 `f(int&)`/
  `f(const int&)` 并存时 `f(5)` 先选中前者再被拒（clang 选后者）。
- **引用绑定判据单点** referenceBindsValueCategory（type.h）：const T& 拒右值。
  ★ 值类别模型按标准：`*p`（[expr.unary.op]/1）与 `v[i]`（[expr.sub]/1）也是
  左值——半份判据会造出反方向的缺陷（漏掉它们 ⇒ `g(*p)` 被误拒）。
- **身份 = 名字 + 形参类型链**（B22）：paramTypeChain（每段 sanitizeSymbolChars）
  只在"同类同名同个数"时挂符号后缀 ⇒ 既有 116 用例零漂移。四处落点（符号定名/
  vtable 认领/成员调用选定/构造函数选定）全部收口。
- **构造函数选定**把推出来的实参类型**传下去**（B22 缺陷④：曾只数个数扔掉
  类型，静默选错构造）。

## §3 诊断类别（异常处理）

本模块的诊断由 `src/sema/semantic_analyzer.cpp` 的 `error()` 打出，输出形态
`[Semantic Error] {行:列}: {文案}`。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 自由函数调用：没有任何候选可行 | `no matching function for call to '{名}' — {原因} ('{实参类型}')` | 否 |
| 2 | 自由函数调用：实参个数太少 | `too few arguments to function call, expected {n}, have {m}` | 否 |
| 3 | 自由函数调用：实参个数太少（只有一个形参时给名字） | `too few arguments to function call, single argument '{参数名}' was not specified` | 否 |
| 4 | 自由函数调用：实参个数太多 | `too many arguments to function call, expected {n}, have {m}` | 否 |
| 5 | 自由函数调用：实参个数太多（只有一个形参时给名字） | `too many arguments to function call, expected single argument '{参数名}', have {m} arguments` | 否 |
| 6 | 成员函数调用：个数在范围内但无可行候选 | `no matching member function for call to '{名}' in class '{类名}' ({n} argument(s) given; 实参类型无法按 [overload.viable] 转换)` | 否 |
| 7 | 构造函数调用：没有接受这些实参的构造函数 | `no matching constructor for '{类名}' with {n} argument(s)` | 否 |
| 8 | 构造函数调用（表达式路径） | `No matching constructor for class '{类名}' with {n} arguments` | 否 |
| 9 | 构造目标不是类类型 | `construction target '{类型}' is not a class type` | 否 |
| 10 | 函数模板调用：没有候选能成功推导 | `no matching function for call to '{名}' (no template candidate deduces successfully)` | 否 |
| 11 | 函数模板的**显式 NTTP 实参**（尚不支持） | `explicit non-type template argument '{值}' for function template '{名}' is not supported yet (only class templates support non-type parameters)` | 否 |

★ 第 2~6 条与 clang++-18 **逐字相同**。
★ 第 1 条的"原因"串来自绑定可行性判据 `argsBindTo`——它与报错 `checkArgBinding` **分开**：
绑定是 [overload.viable] 的一部分，必须在择优**之前**剔候选（B26 的修法）。

## §4 Out of Scope（本模块不做的事）

- **不做转换等级排序**（[overload.icp]）：只判"精确匹配 / 可隐式转换"两档，不分"标准转换 > 用户定义转换 > 提升"。
- **不做用户定义转换序列**：没有 `operator T`，也没有转换构造函数——`std::string` 传给 `void f(const char*)` 这类程序不会被接受。
- **不做默认实参参与的重载裁决**：函数默认实参本项目就没做（见 03-解析/01-声明解析 §4）。
- **argTypes 含 nullptr 时取首个候选**：那是"判不了"（依赖上下文 / SFINAE 探针）的情形，不是"判出来没人行"——B27 修的就是把这两件事混成一件（静默算错）。
- **不做函数模板与普通重载的混合择优中的偏序细化**：偏序在 05-模板域，只做最小可用。
- **不做显式模板实参的函数模板调用的 NTTP 形态**（见第 11 条诊断）。

## §5 观测点（日志键）

**本模块不打独立日志键**——择优原语 `pickBestByArgs` 是纯裁决，不打印。

★ 单候选时**刻意不打日志**（B22 的零漂移策略：既有 116 个集成用例逐字节零漂移）。
可观测痕迹只有两条：

| 时机 | 打的键 | 归属 |
|---|---|---|
| 构造函数被选定（回填 ctorSymbol） | `[ctor] ★ {类名} : {构造函数名}({n} 个实参) ⇒ 选定构造函数符号 {符号}` | 04 语义 |
| 被选中的成员方法（回填 resolvedCalleeSymbol） | `[member] {类}.{方法名}() → {返回类型}    (method)` | 04 语义 |
