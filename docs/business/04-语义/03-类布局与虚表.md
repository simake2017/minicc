## §1 管什么（定位）

ClassLayout：字段偏移、vptr 位置、vtable 槽表、RTTI。Sema 计算，CodeGen 只读。

## §2 关键判据（详细设计）

- **字段定位三级**（B13~B15）：`子对象偏移(viaBase) + 基类布局[baseFieldIndex].offset`。
  FieldInfo 三字段各司其职：declaredName（权威裸名，查找的键）/ viaBase（装着它的
  **直接**基类子对象）/ baseFieldIndex（基类布局里的下标）。★ **显示名曾兼任
  索引，是 B13~B15 同根缺陷**——名字是给人看的，位置才是机器要的。
- **primary 基类三态**（B11）：动态基类里选 primary 摆到 0；一个都没有时
  **vptr 自己占 0**、基类从 8 起。旧判据只写两态 ⇒ 本类自己的 _vptr 与首基类
  撞 0，写基类字段即写坏虚表指针、虚调用跳飞 SIGSEGV（真 miscompile）。
- **vtable 符号单点定名** memberMethodSymbolName(owner, name, paramCount,
  earlierSameNameCount)（B20）：registerFunction 与 vtable 三个落点（主表覆写/
  次表覆写/新条目）共用。**计数口径有坑**：只数排在当前方法**之前**的同名方法。
- **次基类槽原样透传**（B20 缺陷②）：未覆写的槽保留上游符号（X_f），**不**按
  "这条槽属于 Q"重造 Q_f——重造即链接期 undefined reference。
- **槽位认领按签名**（B22）：`virtual int f(); int f(int);` 里非虚的后者曾认领
  前者的槽并被误标 virtual（运行返回 255 的静默算错）——身份 = 名字 + 形参
  类型链。
- **static 成员不进布局**：挂在类名上的全局变量，类内声明 + 类外定义出存储；
  漏定义 odr-use ⇒ 链接期响亮报错（learn/44）。

## §3 诊断类别（异常处理）

本模块的诊断由 `src/sema/semantic_analyzer.cpp` 的 `error()` 打出，输出形态
`[Semantic Error] {行:列}: {文案}`。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 继承说明里的基类名在类注册表里查不到 | `Base class '{名}' not found` | 否 |
| 2 | 多继承里同名字段在两个基类子对象中都有（歧义） | `Member '{名}' is ambiguous in class '{类名}': found in {n} base-class subobjects ({列表})` | 否 |
| 3 | static 成员重复声明 | `duplicate static member '{名}'` | 否 |
| 4 | 非 const 的 static 数据成员在类内给了初始化式 | `non-const static data member must be initialized out of line` | 否 |
| 5 | static 成员的初始化式不是常量表达式 | `static member '{名}' initializer is not a constant expression` | 否 |
| 6 | 初始化列表里写的成员名在类里不存在 | `Member '{名}' not found in class '{类名}' during initializer list` | 否 |
| 7 | `dynamic_cast` 到无共同祖先的类 | `Cannot dynamic_cast '{源类}*' to '{目标类}*': unrelated class types` | 否 |
| 8 | `dynamic_cast` 的操作数不是"到类的指针" | `dynamic_cast operand must be a pointer to a class` | 否 |
| 9 | static 数据成员在类外**漏定义**却被 odr-use | 链接期 `undefined reference to '{符号}'`（src/link/linker.cpp） | 否 |

★ 第 2 条的文案与 clang++-18 **逐字相同**（[class.member.lookup]/8）。
★ 第 9 条是**链接期**才响——编译期全程绿灯（learn/44 记录了这个"漏定义"现场）。

## §4 Out of Scope（本模块不做的事）

- **不做虚继承（virtual base）**：布局里没有 vbase offset 一说，多继承的基类偏移是静态的 `viaBase + baseFieldIndex`。
- **不做空基类优化（EBO）**：空基类照样占位（偏移按普通字段推进）。
- **不做位域（bit-field）与 `alignas`**：字段只有"声明顺序 + 类型宽度"这一个布局自由度。
- **`final` / `override` 不做校验**：写出来不影响布局，也不校验是否真的覆写了虚函数。
- **vtable 槽位不做"次基类重造符号"**：未覆写的槽**原样透传上游符号**（X_f），真覆写才改指本类实现 + thunk——重造即链接期 undefined reference（B20 缺陷②）。
- **RTTI 只做 Itanium 的三种形态**（`__class_type_info` / `__si_class_type_info` / `__vmi_class_type_info`），不做 `typeid` 表达式与 `__dynamic_cast` 的完整 ABI。
- **不做 `dynamic_cast` 到引用 / 到多级层次**：只做了"指针到指针"与"有共同祖先"这一档。

## §5 观测点（日志键）

**本模块不打日志键**——布局与 vtable 的计算过程完全静默（ClassLayout 是纯数据，
vtable 的槽表在 CodeGen 阶段才变成汇编数据段）。

★ 可观测痕迹在**消费方**：

| 时机 | 打的键 | 归属 |
|---|---|---|
| 成员访问命中了某个子对象里的字段 | `[member] {类}.{字段} → {类型}    (offset={n}, size={n})` | 04 语义 |
| 虚调用的动态派发判定 | `[member] {类}.{方法名}() → {返回类型}    (method, virtual)` | 04 语义 |
| 限定名访问的 static 成员 | `[member] {类}.{名}::{成员} → {类型}    (static member, 全局符号 {符号})` | 04 语义 |
| vtable / RTTI 数据段发射 | （无日志，产物在 .s 的 `.data` 段） | 06 代码生成 |
