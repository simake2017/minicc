## §1 管什么（定位）/ 不管什么

- 管：表达式优先级层（赋值→?:→或→与→比较→加法→乘法→一元→初等）、全部语句
  （if/while/for/do-while/switch/break/continue/return/表达式语句/语句块/语句层声明）。
- 不管：语句的语义检查（Sema 的 m_loopDepth/m_switchDepth，→ 04.x）；表达式的
  类型推导（Sema inferType 链）。

## §2 关键判据（详细设计）

- **本语言赋值是【语句】**——不是表达式。为此 for 的 init/incr 两格**局部放宽**
  为"表达式或赋值"（这两格 AST 槽是 StmtPtr）：不放宽会把 `for(i=0;...;i=i+1)`
  这种最普通的教学示例拒之门外。
- **?: 右结合**、中支是**全表达式**（可含赋值式逗号）；顶层包在 parseExpression。
- **逗号表达式的边界**：只在括号内（for 头）开放 `match(Comma)`；调用实参表等处的
  `,` 仍是分隔符——不做语法上下文推导，靠位置白名单。
- **switch 解析**：cond 括号后开放 case/default 标签序列；default 至多一个的
  检查归 Sema（m_caseValueSets 栈，case 值必须常量且防重，文案逐字同 clang）。
- **字面量 fast path**：parseIntLiteral 不打日志（约定，见 02 词法）；模板实参位
  仅当字面量后紧跟运算符时回退解析完整常量表达式（isExprContinuation，**刻意
  不收 Less/Greater**——`Buf<4>` 收尾的 `>` 与大于号同 token，learn/39）。

## §3 诊断类别（异常处理）

本模块的**语法**诊断走 src/parse/parser.cpp 的 `errorAt()`，输出形态
`[Parse Error] {行:列} at '{token}': {文案}`；**语义**诊断由 04 语义域打出（见下表右列备注）。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 表达式首 token 不属任何初等（字面量 / 名字 / 括号 / 构造调用） | `Unexpected token '{token}' in expression` | 否 |
| 2 | `decltype` 后缺左括号 | `Expected '(' after 'decltype'` | 否 |
| 3 | `decltype(...)` 缺右括号 | `Expected ')' to close 'decltype'` | 否 |
| 4 | 限定名 `::` 后缺标识符 | `Expected type name after '::'` | 否 |
| 5 | 表达式里出现无类型（`[infer]` 阶段发现） | `Invalid binary operation types`（04 语义域打出） | 否 |
| 6 | `break` 不在循环或 switch 内 | `'break' statement not in loop or switch statement`（04 语义域打出） | 否 |
| 7 | `continue` 不在循环内 | `'continue' statement not in loop statement`（04 语义域打出） | 否 |
| 8 | `case` 不在 switch 内 | `'case' statement not in switch statement`（04 语义域打出） | 否 |
| 9 | `case` 值不是常量表达式 | `case value is not a constant expression`（04 语义域打出） | 否 |
| 10 | `case` 值重复 | `duplicate case value '{值}'`（04 语义域打出） | 否 |

★ `break` / `continue` 的文案**逐字同 clang**（含 `break` 那句里的 "or switch"——那是给未来
switch 提前留的位置，不是笔误）。

## §4 Out of Scope（本模块不做的事）

- **赋值是【语句】不是表达式**：本语言没有赋值表达式，`a = b` 不能出现在表达式位置（`for` 的 init/incr 两格是**局部放宽**的例外）。因此不做 `int x = (y = 1);` 这类程序。
- **不做区间 for**（range-based for，`for (auto x : v)`）：`parseForStmt` 只收 C 风格三段式。
- **调用实参表里的 `,` 是分隔符**：逗号表达式**只在括号内**开放（for 头），不做语法上下文推导（靠位置白名单）。
- **不做 `co_await` / `co_yield` / `requires` 表达式**：优先级层里没有这三类。
- **`switch` 不做 fallthrough 警告**：不匹配的 case 顺序穿透是自然行为，无诊断。
- **不做位域、向量扩展（`__attribute__`）与对齐说明符（`alignas`）**。

## §5 观测点（日志键）

| 时机 | 打的键 |
|---|---|
| 字符字面量求码点（[lex.ccon] 的翻译结果） | `[parse:literal]` |
| `new` 表达式带模板实参（`new Box<int>(...)`） | `[parse:new]` |
| 模板实参位上的 NTTP 字面量（带形态标注） | `[parse:targ]` |

★ 表达式**类型**的形态行（如 `[infer] IntLiteral(4) → long`）由 04 语义域打出，不在本模块。
