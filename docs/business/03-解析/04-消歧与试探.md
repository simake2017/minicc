## §1 管什么（定位）：TokenCheckpoint（RAII 试探-回滚）

- 构造：快照 m_pos + m_stopAtGreater + 日志进**缓冲栈**；commit 冲刷（成功路径
  输出逐字节不变）；析构未 commit 全维度回卷 + 缓冲丢弃。
- ★ 取舍：**缓冲-冲刷**而非静默开关——成功路径的 [parse:targ] 是真日志，
  静默会让它们也丢行。新状态维度进快照是编译期强制（漏快照编不过）。
- 试探内部**只窄捕获 ParseError**——旧 catch(std::exception) 会把真 bug
  （越界/logic_error）吞成"不是模板"静默降级（learn/45）。

### 四类试探点（全部已过 TokenCheckpoint）

| 试探点 | 判什么 | 备注 |
|---|---|---|
| 模板 id 消歧（表达式层） | `a<b>(c)` 调用还是比较链 | 第一层闸查名字登记表（→ 03.5） |
| 语句层声明 | 声明还是表达式语句 | parseType 全语法试探 |
| 顶层 parseDeclaration | 函数还是全局变量 | 纯试探，永不 commit |
| 类体成员判定 | 方法还是字段 | 纯试探，永不 commit |

## §2 关键判据（详细设计）

- **[stmt.ambig] 两层**：① 语法层（parseType 试探）② 名字层（类型链里任一模板
  id 基名不在登记表 ⇒ 全部推翻）——`a<b>c` 语法上无懈可击，必须问"名字的种类"
  这一个 bit。
- **`<` 消歧三层**：第一层闸 isKnownTemplateName（不在表连试探都不做）→ B32
  试探回滚。**宁宽勿窄**：误收进试探 = 响亮拒收（可发现），漏收 = 方向性错
  （变量被当模板实例发 callq，learn/46 突变实测）。
- **`>` 刻意不收进 isExprContinuation**：`Buf<4>` 收尾 `>` 与大于号同 token，
  收进来 tmpl 21..26 全线漂移（learn/39 协同判据，两处闸不交叉）。
- **m_stopAtGreater**：模板实参表内的常量表达式解析遇裸 `>` 即停；括号分组内
  豁免（`Buf<(2>1)>` 是真比较）。
- ★ 幽灵行教训：B32 前基线固化 14 行试探残留日志无人察觉——**基线会把污染
  固化成契约**（第三次印证）。

## §3 诊断类别（异常处理）

**本模块本身不产生诊断文案**：试探失败抛出的 `ParseError` 一律被窄捕获吞掉，
试探点拿不到判据就走"另一条路"（或让下游阶段去报错）。

★ 下面这张表列的是**试探路径上会被吞掉的 ParseError 文案**——它们不在用户面前出现，
但决定"这次试探为什么没成"，排查时按这张表对号入座。全部走 src/parse/parser.cpp 的 `errorAt()`，
输出形态 `[Parse Error] {行:列} at '{token}': {文案}`。

| # | 试探点撞上的情形 | 诊断文案（被吞掉，不直接面向用户） | 可重试 |
|---|---|---|---|
| 1 | `parseType()` 试探撞上非类型 token | `Expected type name` | 否 |
| 2 | `parseType()` 试探撞上非法的整型家族序列 | `invalid type specifier sequence '{序列}': {原因}` | 否 |
| 3 | 模板模板形参缺 `class` / `typename` | `Expected 'class' or 'typename' after the template parameter list of a template template parameter` | 否 |
| 4 | 嵌套模板模板参数 depth > 1 | `nested template template parameters are not implemented (depth > 1)` | 否 |
| 5 | 表达式首 token 不属任何初等 | `Unexpected token '{token}' in expression` | 否 |
| 6 | `decltype` 括号不配对 | `Expected '(' after 'decltype'` / `Expected ')' to close 'decltype'` | 否 |

★ **窄捕获是硬要求**：旧代码用 `catch(std::exception)`，会把试探内部的真 bug
（越界 / logic_error）吞成"不是模板"的静默降级（learn/45）。现在只捕获 `ParseError`。

## §4 Out of Scope（本模块不做的事）

- **不做 clang 的 `RevertingTentativeParsingAction` 那种统一动作对象**：本项目用 RAII 快照（m_pos + m_stopAtGreater + 日志缓冲栈）实现，代价是新状态维度必须进快照（编译期强制），收益是机制简单。
- **不做错误恢复**：ParseError 一抛即中止本翻译单元（panic 模式），不做 Token 级跳过/同步恢复，代价是"一处语法错误后面全都不报"。
- **不做多错误收集**：没有 `-ferror-limit`，永远只有第一条诊断。
- **试探点只有四处**（模板 id 消歧 / 语句层声明 / 顶层声明 / 类体成员判定）：新增语法若引入新的前瞻点，**必须**走 TokenCheckpoint，否则幽灵行会回来（B32 基线曾固化 14 行试探残留无人察觉）。
- **不做"试探成功即复用解析结果"的路径复用**：试探成功后正式分支会重新 parseType 一次（纯试探永不 commit），代价是重复解析，收益是两条路径的行为完全一致。
- **`<` 消歧只做两层闸**（名字登记表 + B32 试探）：不做 clang 式 `isTemplateArgumentList` 的语法试探（那是 Stage 2/3 的待办）。

## §5 观测点（日志键）

**本模块不打独立日志键**——试探期间的日志进**缓冲栈**，commit 才冲刷（成功路径输出逐字节不变），
未 commit 则整体丢弃。机制上"试探日志不可能再留痕"由 RAII 析构函数保证。

★ 因此本模块的观测手段是**间接**的：

| 观测手段 | 内容 |
|---|---|
| logdiff 基线 | 基线里**没有**任何试探残留行；基线漂移即说明有试探点没走 TokenCheckpoint |
| tests/lang/basics_19 | 断言编译日志中**无** `[parse:type]` / `[parse:targ]` 试探残留 |
| 试探点的源码标注 | parser.cpp 里每个试探点都带 `TokenCheckpoint` 标注（代码地图 §6 提到的"全部试探点带 TokenCheckpoint 标注"） |
