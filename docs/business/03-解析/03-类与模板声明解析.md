## §1 管什么（定位）/ 不管什么

- 管：class/struct 定义体、继承说明符（默认 public，[class.derived]/2）、
  模板头四种形参（类型 `class T`、NTTP `int N`、`template<auto V>`、模板模板
  `template<class> class C`）、推导指引 `Box(T) -> Box<T>;`。
- 不管：成员的语义注册（Sema Pass 1）；模板实参的**语义**校验（Sema
  checkTemplateArguments）。

## §2 关键判据（详细设计）

- **类体方法/字段判定**：TokenCheckpoint 纯试探（永不 commit），消掉手写前瞻
  复制品。这是 parser.cpp 最后一个收口的试探点（B36 批次）。
- **成员模板说明符位置**（B19）：`template<...> static U f(U)` 标准写法在吃完
  形参表后**再认一次** static（收下）；virtual 当场报错（[temp.mem]/2：成员函数
  模板不得 virtual，文案逐字同 clang）。★ 「先声明」与「先出现」是两件事。
- **只做成员函数模板**：成员类模板/成员别名模板/静态数据成员模板在此响亮拒收。
- **推导指引前瞻**：`MyPtr(T)` 与 `MyPtr f(T)` 前两个 token 完全相同——靠
  "配对右括号后是否跟 `->`" 区分；looksLikeDeductionGuide 是纯 token 检查，
  不打日志（const 方法无试探日志，B36 判定不动它）。
- **模板形参表四种形参**的语法归一：parseTemplateDecl 从仅类模板分支扩到
  NTTP/ttp/auto（learn/33、35）；形参表内的 template 头照常收集进名字登记表。

## §3 诊断类别（异常处理）

全部走 src/parse/parser.cpp 的 `errorAt()`，输出形态
`[Parse Error] {行:列} at '{token}': {文案}`。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 写了 `template<>` 却没有在类名后写 `<...>`（全特化必须点明模板实参） | ``extraneous 'template<>' in declaration of class '{名}' —— 写了 `template<>` 却没有在类名后写 `<...>`：全特化必须点明模板实参（如 `template<> struct {名}<int, int>`）；若本意是定义主模板，请去掉 `template<>``` | 否 |
| 2 | 显式 `private` / `protected` 继承 | `'{说明符}' inheritance is not implemented (only public inheritance is); omit the specifier on a struct to get public by default` | 否 |
| 3 | `class` 省略继承说明符（默认私有继承） | `a class default-inherits privately ([class.derived]/2), which is not implemented; write 'public' explicitly or use 'struct'` | 否 |
| 4 | 成员函数模板带 `virtual`（[temp.mem]/2 末句） | `'virtual' cannot be specified on member function templates` | 否 |
| 5 | 成员模板的形参位是模板模板参数 | `template template parameters in member templates are not implemented` | 否 |
| 6 | 嵌套的模板模板参数（depth > 1） | `nested template template parameters are not implemented (depth > 1)` | 否 |
| 7 | 模板模板形参后缺 `class` / `typename` | `Expected 'class' or 'typename' after the template parameter list of a template template parameter` | 否 |
| 8 | 成员模板的形参缺名字 | `Expected parameter name in member template` | 否 |
| 9 | 类体成员的类型位置出现非类型（成员模板 / static / virtual 落错位） | `Expected type name` | 否 |

★ 第 1、4 条的文案与 clang++-18 **逐字相同**（实测对拍）。
★ 第 1 条修的是"此前静默接受"的缺陷（`template<>` 被当主模板），第 9 条修的是 B19 的双向错位。

## §4 Out of Scope（本模块不做的事）

- **成员类模板 / 成员别名模板 / 静态数据成员模板 一律响亮拒收**：本项目**只做成员函数模板**（learn/34 §3.5）。
- **成员函数模板不得 `virtual`**：不是"暂不支持"，是**当场报错**（[temp.mem]/2 是强制义务）。
- **private / protected 继承不实现**；`class` 的默认私有继承也不实现（只有 `struct` 的默认 public 继承走得通）。
- **嵌套模板模板参数 depth > 1 直接报错**，不做"收下再报错"——错误点在解析期暴露，不留到实例化。
- **推导指引只认直接形态**：`Box(T) -> Box<T>;`（模板形态）与 `Two(int) -> Two<int,int>;`（非模板形态）；不做变参指引 `Box(T...) -> Box<T>;`。
- **不做 `final` / `override` 说明符**：写出来会被当成普通标识符路径，不产生校验。
- **模板头的四种形参之外不做形参包**：`template<class... Ts>` 不被接受（模板模板形参的 `class...` 同理，见 05-模板域 §4）。
