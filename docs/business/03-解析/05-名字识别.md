## §1 管什么（定位）

解析期"这个名字是什么种类"的**唯一判定依据**。`NameClassification` 四位并集：
`{isType, isNamespace, isTemplate, isValue(恒 false 占位)}`，键 = (scope, name)。
对齐 clang `Sema::ClassifyName`（`clang/lib/Sema/SemaDecl.cpp:Sema::ClassifyName`）。

## §2 关键判据（详细设计）

- **分层红线**：Parser 只持构造期**前向收集的只读投影**，不持 Sema 活句柄——
  用空间（一份冗余账本）换架构分层（spec 否决记录，唯一权威表述）。
- **前向而非边解析边登记**：支撑先使用后声明；扫描循环不跳已处理区间。
- **收集规则**（5 条）：template 头后名字收 template 位（**不置 type 位**——
  `Box;` 对类模板名保持非类型解释）；struct/class/enum 名收 type 位；
  typedef 取末段标识符；`using X =`（Ident+Assign 形）；`namespace X {`
  推作用域栈按花括号深度配对 + `namespace A = B;`。种子名单收 Sema 内建
  `std::declval`（不经 token 流，构造时注入）。
- **同名跨类并存**：位按 (scope,name) 并集累积——`int S; struct S;` 合法。
- **签名规则（防错铁律）**：消费点只依赖**位命中**做正向判定；查不到 = 未知 =
  全 false，**禁止反向推断**（"查不到 ⇒ 不是"是这类消歧最常见的错法，learn/47 §6）。

## §3 诊断类别（异常处理）

**名字登记表本身不产生诊断**（它是只读的查表结构，没有失败路径）。
本模块相关的诊断全部由 **04 语义域**在裁决"这个名字能不能用"时打出。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 语句层裸名 `S;`：S 可见但**不是**类型名（走表达式路径仍找不到） | `use of undeclared identifier '{名}'`（src/sema/semantic_analyzer.cpp:3758） | 否 |
| 2 | Sema 侧限定模板名裁决：`N::B` 在命名空间 N 里不存在 | `no template named '{名}' in namespace '{命名空间}'`（src/sema/semantic_analyzer.cpp:1026） | 否 |
| 3 | 名字从未作为类/类型被声明过 | ``unknown type name '{名}' —— 该名字没有作为类/类型被声明过。（语句层的声明/表达式歧义（`a < b > c;`、裸 `S;`）由语义期的名字可见性判据裁决（docs/learn/48）；能走到这一步的 `名字 标识符/;` 是【真正的】未知类型名。）``（src/sema/semantic_analyzer.cpp:1228） | 否 |

★ 第 2 条是 B38 的修法：**由宽改严**——旧行为把 `N::B` 默默绑到全局 `B`（静默算错，方向性错），
现在查不到就报 `no template named 'B' in namespace 'N'`（**与 clang 逐字**；clang 另附
"did you mean simply 'B'?" 建议，本项目不做）。

## §4 Out of Scope（本模块不做的事）

- **value 位恒 false（按拍板占位，不参与判定）**：未声明的名字**不会**按 C++20 规则被当成 template-id 解释——探针 `unknown<x>(y)` 在 clang 报 "use of undeclared identifier 'x'"，minicc 走比较链报 "Undefined variable 'unknown'"。分水岭是"这个名字**声明过**吗"，登记表至今没有 value 位（learn/47 登记的待办）。
- **Parser 侧只有构造期前向收集的只读投影**，不做"边解析边 `ActOn*` 登记"的正规模式（那是 Stage 3）。
- **登记表已降级为候选过滤器**：「值不值得让 Sema 查一下」，**不是**可见性的答案——可见性裁决权在 Sema（learn/48）。
- **宏名不进登记表**：预处理展开后的名字不在登记范围内。
- **Parser 侧不做限定名的可见性判定**：`N::B` 的裁决由 **Sema 自己的符号表**回答（`lookupVisibleType` + 按完整作用域查模板注册表），**不再经登记表**——B38 已把 Sema 侧那个消费点退场，`classifyQualified` 现为零调用点。
- **收集器不跳已处理区间**：嵌套 `template<...>` 头照常收集进登记表，但循环不回头重扫已处理区间（避免重复登记与死循环）。

## §5 观测点（日志键）

**本模块不打日志**——名字登记表是纯查表结构，没有可观测的时机。

★ 消费点的可观测痕迹（由消费方打出，不属于本模块）：

| 时机 | 打的键 | 归属 |
|---|---|---|
| 语句层裸名被判为无声明符声明 | `[parse:stmt]` | 03 解析（**登记表消费点**） |
| 限定模板名裁决（`N::B` 不存在时） | `[sema:alias]` | 04 语义（诊断仍在，但 B38 后**不再经登记表**） |
