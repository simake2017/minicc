## 核心机制与判据

- **递归下降**：每条文法规则一个函数，函数互调自然长成 AST。每步只看 1 个前瞻 Token。
- **TokenCheckpoint 试探-回滚**（RAII）：快照 m_pos + m_stopAtGreater + 日志进缓冲栈；
  commit 才冲刷（成功路径输出逐字节不变），析构未 commit 全维度回卷——**试探日志
  机制上不可能再留痕**。parser.cpp 全部试探点（模板-id 消歧、语句层声明、顶层
  声明、类体成员判定）都过了这一关。试探内部只窄捕获 ParseError，真 bug 不被吞成
  "不是模板"静默降级。
- **[stmt.ambig] 声明 vs 表达式**：语句层前瞻 = TokenCheckpoint + parseType() 试探；
  类型链里任一模板 id 层基名**不在名字登记表** ⇒ 全部推翻（语法无懈可击时必须问
  "名字的种类"这一个 bit）。
- **名字登记表**（业务判据唯一来源，spec 已签字）：`NameClassification{type, namespace,
  template, value(占位)}` 四位并集 + (scope, name) 键；Parser 构造期前向收集只读
  投影，**Parser 不持 Sema 活句柄**（分层红线）。签名规则：消费点只依赖位命中做
  **正向**判定，查不到 = 未知 = 宁宽勿窄（误收进试探是响亮拒收，漏收是方向性错）。
- **`<` 消歧三层**：第一层闸查登记表（不在表连试探都不做）→ B32 试探回滚。
  `>` 刻意不进 isExprContinuation 判据（`Buf<4>` 的收尾 `>` 与大于号同 token）。
- **零 RTTI 分派**：handler 只要引用 → visit 访问者（accept 虚分派）；还要
  shared_ptr 所有权或返回值 → 标签分派（switch）。accept 必须类内 inline 定义，
  否则成 Itanium 键函数、vtable 链接期爆炸。
