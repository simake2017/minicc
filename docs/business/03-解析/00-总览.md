## §2 关键判据（详细设计）

- **递归下降**：每条文法规则一个函数，函数互调自然长成 AST。每步只看 1 个前瞻 Token。
- **TokenCheckpoint 试探-回滚**（RAII）：快照 m_pos + m_stopAtGreater + 日志进缓冲栈；
  commit 才冲刷（成功路径输出逐字节不变），析构未 commit 全维度回卷——**试探日志
  机制上不可能再留痕**。parser.cpp 全部试探点（模板-id 消歧、语句层声明、顶层
  声明、类体成员判定）都过了这一关。试探内部只窄捕获 ParseError，真 bug 不被吞成
  "不是模板"静默降级。
- **[stmt.ambig] 声明 vs 表达式**：语句层前瞻 = TokenCheckpoint + parseType() 试探；
  类型链里任一模板 id 层基名**不在名字登记表** ⇒ 全部推翻（语法无懈可击时必须问
  "名字的种类"这一个 bit）。
- **名字登记表**（业务判据唯一来源，spec 已签字）：`NameClassification{type, namespace,
  template, value(占位)}` 四位并集 + (scope, name) 键；Parser 构造期前向收集只读
  投影，**Parser 不持 Sema 活句柄**（分层红线）。签名规则：消费点只依赖位命中做
  **正向**判定，查不到 = 未知 = 宁宽勿窄（误收进试探是响亮拒收，漏收是方向性错）。
- **`<` 消歧三层**：第一层闸查登记表（不在表连试探都不做）→ B32 试探回滚。
  `>` 刻意不进 isExprContinuation 判据（`Buf<4>` 的收尾 `>` 与大于号同 token）。
- **零 RTTI 分派**：handler 只要引用 → visit 访问者（accept 虚分派）；还要
  shared_ptr 所有权或返回值 → 标签分派（switch）。accept 必须类内 inline 定义，
  否则成 Itanium 键函数、vtable 链接期爆炸。

## §3 诊断类别（异常处理）

本域的**语法**诊断全部由 `src/parse/parser.cpp` 的 `errorAt()` 打出，输出形态
`[Parse Error] {行:列} at '{token}': {文案}`。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 类型位置出现非类型（`static` / `virtual` 落错位） | `Expected type name` | 否 |
| 2 | 内置整型家族说明符序列非法 | `invalid type specifier sequence '{序列}': {原因}` | 否 |
| 3 | 表达式首 token 不属任何初等 | `Unexpected token '{token}' in expression` | 否 |
| 4 | 模板实参表未闭合 | `Expected '>' after template arguments` | 否 |
| 5 | 成员函数模板带 `virtual`（[temp.mem]/2） | `'virtual' cannot be specified on member function templates` | 否 |
| 6 | 写了 `template<>` 却没在类名后写 `<...>` | ``extraneous 'template<>' in declaration of class '{名}' —— 写了 `template<>` 却没有在类名后写 `<...>`：全特化必须点明模板实参（如 `template<> struct {名}<int, int>`）；若本意是定义主模板，请去掉 `template<>``` | 否 |

★ 逐条的完整清单见 01~05 五份子文档各自的 §3；**语句层的语义诊断**（`use of undeclared identifier`）
归 04 语义域。

## §4 Out of Scope（本模块不做的事）

- **本页是索引页，不承载判据细节**：五份子文档（01~05）各自负责一块，本页只做"子文档导航 + 机制总表"。
- **不回答"这个名字在不在作用域里可见"**：可见性裁决权在 **Sema**（04 语义域，learn/48）。Parser 侧只有构造期只读投影（05-名字识别），且该投影已降级为**候选过滤器**。
- **不含端到端走线**：跨层的调用链归 `docs/lines/**`。
- **不含变更计划**：一次改动怎么做归 `docs/specs/**` + `docs/designs/**`。
- **不持 Sema 活句柄**：Parser 只能通过窄的只读查询接口向 Sema 提问并服从答复（分层红线，见 05-名字识别 §2）。
- **不做错误恢复**：ParseError 一抛即中止本翻译单元，不做 Token 级同步恢复（panic 模式，见 04-消歧与试探）。

## §5 观测点（日志键）

| 时机 | 打的键 |
|---|---|
| 类型说明符序列归一（内置整型家族 / const 前缀） | `[parse:type]` |
| 语句层裸名被判为声明（type 位命中） | `[parse:stmt]` |
| 模板头解析（template 声明、形参表） | `[parse:template]` |
| 模板实参表（NTTP 实参带形态） | `[parse:targ]` |
| 类体成员判定（成员模板 / static 成员函数） | `[parse:member]` |
| 类声明（特化模式 / 前向声明） | `[parse:class]` |
| 类型别名（using / typedef） | `[parse:alias]` |
| 推导指引 | `[parse:guide]` |
| 字符字面量求码点 | `[parse:literal]` |
| `new` 表达式带模板实参 | `[parse:new]` |
| 未命名形参合成内部名 | `[parse:param]` |
| 后置 const 成员函数 | `[parse:fct]` |

★ **试探点的日志不在此表**：试探期间的日志进**缓冲栈**，commit 才冲刷（成功路径输出逐字节不变），
未 commit 则整体丢弃——所以基线里**看不到**试探残留（回归由 tests/lang/basics_19 断言）。
