## §1 管什么（定位）/ 不管什么

- 管：局部变量、全局变量、函数声明/定义、类外成员定义（`int C::f() {}`）、
  类型别名（using/typedef）、枚举、直接初始化 `Type name(args);`、数组声明符后缀。
- 不管：类体内的成员判定（→ 03.3）、模板头本身（→ 03.3）、类型该是什么（Sema，→ 04.1）。

## §2 关键判据（详细设计）

- **语句层 vs 表达式**：[stmt.ambig] 全交给「TokenCheckpoint + parseType 试探」
  （→ 03.4），声明分支不再手写前瞻复制品。B16 判据等价移植：模板 id 语法 = 本层
  或嵌套限定者链任一层有实参表。
- **函数 vs 全局变量**（parseDeclaration 顶层）：TokenCheckpoint 纯试探
  （永不 commit——拿判据即回卷含日志，正式分支重新 parseType），窄捕获 ParseError。
- **直接初始化**：CTAD 需要才补的 `Type name(args);` 文法（learn/28）。
- **数组声明符后缀** `T a[N]`：parseArrayDeclaratorSuffix 提取 `[ expr ]`，
  挂接局部/全局/成员字段三处声明点；N 的求值归 Sema（→ 06 数组）。
- **类外定义四校验**（static 成员那批）：类存在 / 声明过 / **equals 同类型**
  （typeCompatible 会误放行 long vs int）/ 限定者必须在类注册表
  （第一版用"名字含 ::"把命名空间成员误伤）。

## §3 诊断类别（异常处理）

本模块的诊断走 `src/parse/parser.cpp` 的唯一出口 `errorAt()`，输出形态
`[Parse Error] {行:列} at '{token}': {文案}`。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 类型说明符位置出现非类型（`static` / `virtual` / `struct` 等落在类型位） | `Expected type name` | 否 |
| 2 | 内置整型家族说明符序列非法 | `invalid type specifier sequence '{序列}': {原因}`（原因取自 `cannot be both 'signed' and 'unsigned'` / `'short' appears more than once` / `'long' appears more than once (at most 'long long')` / `'int' appears more than once`） | 否 |
| 3 | 全局变量声明缺名字 | `Expected global variable name` | 否 |
| 4 | 全局变量声明缺分号 | `Expected ';' after global variable declaration` | 否 |
| 5 | 枚举声明缺 `enum` 关键字 | `Expected 'enum'` | 否 |
| 6 | 枚举声明缺左花括号 | `Expected '{' in enum declaration` | 否 |
| 7 | 枚举项缺名字 | `Expected enum item name` | 否 |
| 8 | 枚举声明缺右花括号 | `Expected '}' after enum items` | 否 |
| 9 | 枚举声明缺分号 | `Expected ';' after enum declaration` | 否 |
| 10 | 命名空间声明缺 `namespace` 关键字 | `Expected 'namespace'` | 否 |
| 11 | 命名空间声明缺名字 | `Expected namespace name` | 否 |
| 12 | 命名空间声明缺左花括号 | `Expected '{' in namespace declaration` | 否 |
| 13 | 命名空间声明缺右花括号 | `Expected '}' after namespace declaration` | 否 |
| 14 | `using` 别名声明缺名字 | `Expected alias name in using declaration` | 否 |
| 15 | `using` 别名声明缺 `=` | `Expected '=' in using declaration` | 否 |
| 16 | `using` 别名声明缺分号 | `Expected ';' after using declaration` | 否 |
| 17 | 语句层裸名既不是可见类型名也不是已声明的名字 | `use of undeclared identifier '{名}'`（该文案由 04 语义域打出） | 否 |

★ **语法错误一律 panic 模式**：抛 `ParseError` 即中止本翻译单元，不做 Token 级跳过/同步恢复，
"每处语法错误恰好一条报告"。

## §4 Out of Scope（本模块不做的事）

- **不做函数默认实参**：形参表里没有 `= 表达式` 的语法（`hasDefault` 只在**模板形参**上存在）。
- **类外成员定义不带后置 const**：`int C::f() const {}` 不被接受（`const` 成员函数的识别只发生在类体内的 parseMethodDecl，src/parse/parser.cpp:2038）。
- **不做 `using Base::f;`**：把隐藏名字从基类拉回派生类的语法未实现。
- **枚举只支持整型字面量初始化式**：`enum E { A = 1 };` 里 `A = 表达式` 若不是整型字面量，值留 0（解析期不报错，CodeGen 期处理）。
- **`enum class` 只做"作用域化"这一个动作**：底层类型可写（`enum E : int {}`），但**不做**枚举项的溢出位宽判定与 `operator<<`。
- **不做 `constexpr` 变量的存储期区分**：`constexpr` 关键字在 04 语义域登记编译期常量表（learn/40），解析域只负责把它带进 AST。
- **不做声明与定义的区分**：`int f();` 与 `int f() {}` 在解析期同形，区分靠 Sema 的三趟扫描（04.2）。

## §5 观测点（日志键）

| 时机 | 打的键 |
|---|---|
| 类型说明符序列归一（内置整型家族计数 → 唯一 TypeKind） | `[parse:type]` |
| 语句层裸名被判为声明（名字登记表 type 位命中） | `[parse:stmt]` |
| `using` / `typedef` 类型别名 | `[parse:alias]` |
| 未命名形参合成内部名（[dcl.fct]/3） | `[parse:param]` |
