# 05.4 特化与偏序 —— 三个模板竞争一个名字

> 上级：[00-总览](00-总览.md）。

- 读者：改特化择优或偏序裁决的开发者
- 审法：三路择优顺序固定（全特化 → 偏特化 → 主模板）；偏序用合成实参互推
- 名词版本：v1

## §1 管什么（定位）

类模板特化体系：主模板 / 偏特化 / 全特化的择优，与偏特化之间的偏序裁决。

## §2 关键判据（详细设计）

- **三路择优**：实参表先进全特化表（精确匹配即中）→ 偏特化表逐个
  matchPattern → 都不中落主模板。**特化模式含值位**（specPattern 是
  vector<TemplateArg> 不是 vector<TypePtr>）——`enable_if<true,T>` 的地基；
  拆掉"实参含值位就跳过特化"的旧守卫。
- **matchPattern 结构检查**：引用结构要逐位对（`Probe<int>` **不**匹配
  `Probe<T&>`——learn/20 顺带修复的静默选错）。
- **偏序 [temp.class.order]**（learn/21）：两个偏特化都匹配时用**合成实参**
  互推——给每个形参造唯一占位类型 `$ord_` 前缀，A 能推 B 且 B 不能推 A ⇒
  A 更特化；dominance 循环 ⇒ 歧义报错。完整实现，非近似。
- **★ 两个曾静默接受的错法**（learn/20 负向 44/45）：`template<>` 却不写
  `<...>`（被当主模板）与全特化模式用了未声明的名字（永不匹配且零报错）——
  修复点分别在 parseClassDecl 的守卫与 processTemplateDecl 的 ExplicitSpec 分支。
  **判据的"缺失"比"写错"更难发现**：写错会报错，缺了什么都不发生。

## §3 诊断类别（异常处理）

本模块的诊断由 `src/sema/semantic_analyzer.cpp` 的 `error()` 打出（解析期的
`template<>` 守卫由 src/parse/parser.cpp 打出），输出形态
`[Semantic Error] {行:列}: {文案}`。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 两个偏特化同样特化（偏序成环，无一更特化） | `ambiguous partial specializations of '{名}' for <{实参}>: {候选列表} are equally specialized, none is more specialized than the others` | 否 |
| 2 | 全特化模式里出现模板形参名（`template<>` 的形参表是空的） | ``use of undeclared template parameter '{名}' in explicit specialization of '{模板名}' —— `template <>` 的形参表是空的，模式里不能出现模板形参名`` | 否 |
| 3 | 全特化模式里出现未声明的名字（永不匹配且零报错——此前是静默接受） | ``use of undeclared identifier '{名}' in explicit specialization pattern of '{模板名}' —— `template <>` 的形参表是空的，模式里每个名字都必须是【真实类型】（如 int / MyClass）；若本意是偏特化，请把形参写进 template<...> 并改用 `template <class {名}> struct {模板名}<...>``` | 否 |
| 4 | 写了 `template<>` 却没有在类名后写 `<...>`（被当主模板——此前是静默接受） | ``extraneous 'template<>' in declaration of class '{名}' —— 写了 `template<>` 却没有在类名后写 `<...>`：全特化必须点明模板实参（如 `template<> struct {名}<int, int>`）；若本意是定义主模板，请去掉 `template<>```（解析期，`[Parse Error]`） | 否 |
| 5 | 类模板实参个数多于形参表 | `class template '{名}' expects at most {n} argument(s), but {m} given` | 否 |
| 6 | 类模板实参个数少于形参表（且缺的那个形参无默认值） | `class template '{名}' expects at least {n} argument(s) (parameter '{形参名}' has no default), but {m} given` | 否 |

★ 第 2、3、4 条修的都是**"静默接受"**——写错不会报错，只会算错或什么都不发生。
★ **判据的"缺失"比"写错"更难发现**：写错会报错，缺了什么都不发生（learn/20 的教训）。

## §4 Out of Scope（本模块不做的事）

- **不做 NTTP 特化模式**（`Box<int, N>` 这样的偏特化里带值位）：值位参与模式的地基已铺（specPattern 改成 `vector<TemplateArg>`，learn/35），但 `template<class T, int N> struct Box<T, N>` 的偏特化**未实现**。
- **不做类外定义的特化成员**：`template<> void Box<int>::f() {}` 不被接受。
- **不做变量模板的特化**（变量模板本身也没做）。
- **偏序只覆盖类模板偏特化之间**：合成类型前缀 `$ord_` + dominance 循环这套完整实现（learn/21）是给**类模板偏特化**用的；函数模板偏序在 05-模板/01 侧只做最小可用。
- **`matchPattern` 不做隐式转换匹配**：结构必须逐位对上（`Probe<int>` **不**匹配 `Probe<T&>`），不做"实参类型 convertible 就算匹配"。
- **不做显式实例化指令**（`template class Box<int>;`）。

## §5 观测点（日志键）

| 时机 | 打的键 |
|---|---|
| 类模板特化择优（选定结果） | `[spec:select] ★ selecting class template '{名}' for <{实参}>` |
| 全特化命中 | `[spec:select]   ├─ ① explicit specialization matched (exact argument equality) → USING IT` |
| 全特化未命中 | `[spec:select]   ├─ ① no explicit specialization matched` |
| 偏特化模式匹配成功 | `[spec:select]   ├─ ② 候选：'{名}<{模式}>' 匹配成功` |
| 偏特化未命中 | `[spec:select]   ├─ ② 候选不匹配：{原因}` |
| 只有一个偏特化候选 | `[spec:select]   │  唯一候选 → 直接选中 '{名}<{模式}>'` |
| 多个偏特化同时匹配 → 进入偏序裁决 | `[spec:select]   │  ★ {n} 个偏特化同时匹配 → 进入 [temp.class.order] 偏序裁决` |
| 偏序裁决出最特化者 | `[spec:select]   │  ⇒ 最特化者：'{名}<{模式}>' → USING IT` |
| 落回主模板 | `[spec:select]   └─ ③ falling back to PRIMARY template` |
| 特化模式在类声明处被识别 | `[parse:class] ★ specialization pattern for '{名}'` |
| 模板实参逐位绑定 | `[sema:targ] ✓ param {位}: '{形参名}' ({形态}) ← {实参}` |
