## §1 管什么（定位）

TemplateInstantiator：蓝图 AST → 实例 AST 的深拷贝+替换，与实例缓存/身份管理。

## §2 关键判据（详细设计）

- **替换分两层**：类型位置走 substituteType（Case 1~5.8），表达式位置走
  cloneExpr——NTTP 引入后两者必须都管（learn/18）。
- **Case 5.5 / 5.8（替换当场解糖）**：依赖限定者查成员表/别名表，失败即
  Sfinae::fail——那里正是 [temp.deduct]/8 的**直接上下文**，过了这村没这店。
- **★ 替换 ≠ 实例化**（learn/28）：函数实例化后签名里残留的半成品 `MyPtr<int>`
  必须再过一次 resolveType 才成 `MyPtr_int`——否则函数体成员访问全线报错。
- **实例身份 = 无损键** losslessArgumentsKey：值位形态必须保留（K<2+2> ≠
  K<4L> 的键）；实例名与缓存键同源于 renderArgLossless。★ toString 非单射
  撞键的两次教训（learn/23、35）。
- **实例步骤 5.x**（instantiateClassTemplate）：搬字段/方法/别名/成员模板
  （5.6，只替换**外层**形参——内层 U 原样保留才有调用点可推导）/静态成员
  （5.7）。★ 三种错法：忘了搬（拒收合法程序）、就地改蓝图（第二个实例串
  第一个绑定）、内层也替换（无可推导）。
- **全量而非惰性**（对照 clang 的按需实例化）：一次性克隆整个蓝图——
  教学取舍，换来实现简单、日志可观测。

## §3 诊断类别（异常处理）

本模块自己抛的诊断走 `std::runtime_error`，输出形态 `[Instantiate Error] {文案}`；
经语义层转到用户面前的走 `[Semantic Error] {行:列}: {文案}`。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 实例化时实参个数与形参表不符（直接调 TemplateInstantiator 的兜底路径） | `[Instantiate Error] template '{名}' expects {n} argument(s), got {m}` | 否 |
| 2 | 类型形参位收到值实参（形态自检兜底） | `[Instantiate Error] template argument {位} for '{模板名}' ('{形参名}') must be a type, but '{实参}' is a value` | 否 |
| 3 | NTTP 形参位收到类型实参（形态自检兜底） | `[Instantiate Error] template argument {位} for '{模板名}' ('{形参名}') must be a value, but '{实参}' is a type` | 否 |
| 4 | 两个不同实例清洗后得到同一个汇编符号名（实例名撞车） | `[Instantiate Error] 实例名撞车：'{无损键1}' 与 '{无损键2}' 清洗后都得到汇编符号名 '{符号}'。两者是不同类型，必须产出不同符号 —— 请给实例名清洗规则（template_instantiation.cpp 的 Step 2a）补上区分字符。` | 否 |
| 5 | 类模板名被当普通类型用（没给模板实参） | `'{名}' is a class template; provide template arguments (e.g. {名}<int>)` / `'{名}' is an alias template; provide template arguments (e.g. {名}<int>)`（class 与 alias 两形态） | 否 |
| 6 | 全特化模式里出现模板形参名（`template<>` 的形参表是空的） | ``use of undeclared template parameter '{名}' in explicit specialization of '{模板名}' —— `template <>` 的形参表是空的，模式里不能出现模板形参名`` | 否 |
| 7 | 全特化模式里出现未声明的名字 | ``use of undeclared identifier '{名}' in explicit specialization pattern of '{模板名}' —— `template <>` 的形参表是空的，模式里每个名字都必须是【真实类型】（如 int / MyClass）；若本意是偏特化，请把形参写进 template<...> 并改用 `template <class {名}> struct {模板名}<...>``` | 否 |
| 8 | 别名模板递归展开 | `recursive alias template instantiation '{名}' —— 别名模板的底层类型里又用到了它自己，展开会无限递归` | 否 |

★ 第 4 条是"拿给人看的字符串当机器用的键"教训的**守门人**：两个不同实例撞成同一个汇编符号
就是**静默算错**（两个类型共用一份代码），所以这里响亮报错而不是让它过去。

## §4 Out of Scope（本模块不做的事）

- **不做按需（惰性）实例化**：对照 clang 的按需实例化，本实现**全量克隆**整个蓝图——教学取舍，换来实现简单、日志可观测。
- **不做 `extern template` 显式实例化声明**，也不做实例化定义的显式语法。
- **不做变量模板**（`template<class T> T pi = 3.14;`）。
- **实例化后不再回查特化**：实例化出的类**不参与**偏特化/全特化的二次择优（择优发生在实例化**之前**，见 05-模板/04）。
- **不做实例的"出身"信息在 Type 上的完整保留**：本实现用 `templateOriginName` / `templateOriginArgs` 两个字段补齐（clang 的实例是带实参表的 Decl，天然带得住）。
- **替换 ≠ 实例化**这条已知开销不在消除之列：实例化函数后签名里残留的半成品模板 id 必须再过一次 `resolveType`（learn/28）——这是**已知代价**，不是待修的 bug。

## §5 观测点（日志键）

| 时机 | 打的键 |
|---|---|
| 类模板实例化：缓存命中 | `[instantiate:class] cache hit: {键} (skip re-instantiation)` |
| 类模板实例化：按需实例化开始 | `[instantiate:class] ★ on-demand instantiation: {键}` |
| 类模板实例化：完成 | `[instantiate:class] ✔ {键} ready ({n} bytes, {m} method(s))` |
| 实例名 → 汇编符号前缀 | `[instantiate:name] '{无损键}' → 汇编符号前缀 '{符号}'` |
| 替换表构造（逐形参） | `[subst:map] '{形参名}' ({类型}) := {实参}` |
| 特化场景下由模式匹配提供的替换 | `[subst:map] (specialization) substitution supplied by pattern matching: ...` |
| 方法克隆：返回类型与形参的替换 | `[clone:method] '{方法名}' return type: {前} → {后}` / `[clone:method]   param '{形参名}' : {前} → {后}` |
