## §2 关键判据（详细设计）

- **推导 = 受限合一**（Hindley-Milner 简化版）：逐对 (模式 P, 实参 A) 匹配解出
  形参绑定；同一参数两次绑定必须一致。调用点 A 侧早解糖 ⇒ P 侧也要解
  （desugarAlias，缺一即静默剔候选）。`T<T1...>` 结构合一是 [temp.deduct.type]/8。
- **实例化 = 结构化替换 [temp.subst]**：深拷贝蓝图 AST，类型位置走
  substituteType（Case 1~5.8），表达式位置走 cloneExpr；★ **替换 ≠ 实例化**——
  实例化函数后签名里残留的半成品模板 id 必须再过一次 resolveType。
- **实例身份 = 无损实参键**（losslessArgumentsKey）：值位形态必须保留
  （K<2+2> 与 K<4L> 是两个实例）；★ **拿给人看的字符串当机器用的键，早晚出事**
  （toString 非单射、auto 形参撞键两次教训）。
- **SFINAE 三方协议**（独立模块 sfinae.h）：SubstitutionFailure 异常信号 +
  Sfinae::attempt 吸收器 + SfinaeContext 直接上下文；void_t 探测惯例（CWG 1558）。
  依赖类型名 `typename T::type` 在**替换当场**查成员表解糖，查不到即软失败。
- **偏序裁决 [temp.class.order]**：合成类型前缀 `$ord_` + dominance 循环 + 歧义报错。
- **类模板特化三路择优**：主模板 vs 偏特化（模式匹配 + 特化更优）vs 全特化
  （`template<>` 显式标记）；NTTP 值位参与模式（enable_if 地基）。
- **两阶段查找**：非依赖名定义期查表、依赖名实例化期再查——名字登记表是
  解析期那半边的唯一依据。
- **CTAD + 推导指引**（learn/28）：与函数模板推导同一套合一反向使用；显式指引
  优先于构造函数。
- **别名模板不是新类型**（learn/27）：只有解糖没有实例化，三处解糖点缺一不可。

## §3 诊断类别（异常处理）

本域的诊断分两个出口：语义层走 `src/sema/semantic_analyzer.cpp` 的 `error()`
（`[Semantic Error] {行:列}: {文案}`），实例化层走 `src/sema/template_instantiation.cpp`
（`[Instantiate Error] {文案}`）。编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 函数模板调用：没有候选能成功推导 | `no matching function for call to '{名}' (no template candidate deduces successfully)` | 否 |
| 2 | 类模板实参个数与形参表不符 | `class template '{名}' expects at most {n} argument(s), but {m} given` | 否 |
| 3 | NTTP 实参的值不能表示成形参类型（可表示性判据，B17） | `non-type template argument evaluates to {值}, which cannot be narrowed to type '{形参类型}'` | 否 |
| 4 | 两个偏特化同样特化（偏序成环） | `ambiguous partial specializations of '{名}' for <{实参}>: {候选列表} are equally specialized, none is more specialized than the others` | 否 |
| 5 | 全特化模式里出现未声明的名字（此前是静默接受） | ``use of undeclared identifier '{名}' in explicit specialization pattern of '{模板名}' —— `template <>` 的形参表是空的，模式里每个名字都必须是【真实类型】（如 int / MyClass）；若本意是偏特化，请把形参写进 template<...> 并改用 `template <class {名}> struct {模板名}<...>``` | 否 |
| 6 | 依赖限定者里的成员名不是类型（硬错误） | `no type named '{名}' in '{类名}'` | 否 |

★ 逐条的完整清单见 01~06 六份子文档各自的 §3。

## §4 Out of Scope（本模块不做的事）

- **本页是索引页，不承载判据细节**：六份子文档（01~06）各自负责一块，本页只做"子文档导航 + 机制总表"。
- **不含模板实参的语义校验**：`checkTemplateArguments`（实参个数 / 形态 / 可表示性）在 04 语义域。
- **不含实例产物的代码生成**：实例化出的是 AST，AST 怎么变成汇编在 06 域。
- **不含端到端走线**：跨层的调用链（一条模板实参从调用点到实例化）归 `docs/lines/**`。
- **不含变更计划**：一次改动怎么做归 `docs/specs/**` + `docs/designs/**`。
- **不做参数包（parameter pack）**：变参模板、`class... Ts`、包展开一律不支持——形参表只认四种（类型 / NTTP / 模板模板 / auto）。
- **不做 concept / requires 子句**：SFINAE 探测惯用房（`enable_if` + `void_t`）是本项目的等价手段。
