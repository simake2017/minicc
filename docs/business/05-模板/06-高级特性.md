## §1 管什么（定位）

四个互相咬合的模板特性：**别名模板**（解糖，不是新类型）、**CTAD + 推导指引**
（由构造实参反推类模板形参）、**成员模板**（类内的函数模板）、**模板模板参数**
（模板当模板实参）。四者共用 05-模板域的同一套合一算法（`deducePair`）与
同一套替换引擎（`substituteType`），本篇只讲各自的**特有判据**。

## §2 关键判据（详细设计）

### 别名模板（learn/27）

- **别名不是新类型**（[temp.alias]/1）⇒ 没有"实例化"只有"解糖"，三处解糖点
  缺一不可：① 使用点（resolveType 模板 id 分支，排在类模板分支**之前**——
  两者语法同形，只能靠注册表区分）② 替换期 Case 5.8（当场解，失败即软失败）
  ③ 推导期 desugarAlias（→ 05.1，最易漏）。
- 曾静默接受的错法：NTTP 名在实参位被 Parser 误建为 Class 节点——替换期按
  "表里绑的是值"还原成值实参。

### CTAD + 推导指引（learn/28）

- CTAD 只在**直接初始化**触发；显式指引优先于构造函数（指引存在的意义就是
  改写默认规则）；非模板形态 `Two(int) -> Two<int,int>;` 补构造推不出的形参。
- 前瞻 = 配对右括号后是否 `->`（→ 03.3）。

### 成员模板（learn/34）

- 类内 `Acc::add(T)` 推导复用同一套合一；符号用 `类名_方法名_实参后缀`。
- **类模板里的成员模板是交叉点**（B18）：两层形参绑定时机不同——5.6 步骤只
  搬+只换外层（→ 05.2）。★ 边界表要按**组合**列，只按特性列会漏交叉点。
- static 收下 / virtual 拒收（[temp.mem]/2，文案逐字同 clang）；只做函数模板。

### 模板模板参数（learn/33，[temp.arg.template]/2）

- **逐位签名匹配**（P0522R0）：① 位数相同 ② 逐位同 kind ③ 值位声明类型
  相同。口径全部以 clang++-18 -std=c++20 探针实测确定（旧规则"多出位有默认
  实参即可"已废）。
- **静默接受修复**：`Wrap<Box<int>, int>` 拿模板特化类型填模板位——名字段都
  是 "Box" 骗过守卫、`<int>` 静默蒸发且产物与 `Wrap<Box,int>` 逐字节相同
  （连"算错"症状都没有）。修法：守卫补 `!arg.type->templateArgs.empty()`。
- 别名模板可作模板模板实参（形参表取别名自身）；**嵌套 depth>1 直接报错**；
  KeyOf 静态成员函数是双栖约束取舍（→ 08）。

## §3 诊断类别（异常处理）

本模块的诊断由 `src/sema/semantic_analyzer.cpp` 的 `error()` 打出（成员模板的
`virtual` / 模板模板参数的限制由 src/parse/parser.cpp 打出），输出形态
`[Semantic Error] {行:列}: {文案}` / `[Parse Error] {行:列} at '{token}': {文案}`。
编译期诊断一律**不可重试**。

| # | 触发情形 | 诊断文案 | 可重试 |
|---|---|---|---|
| 1 | 别名模板名被当普通类型用（没给模板实参） | `'{名}' is a class template; provide template arguments (e.g. {名}<int>)` / `'{名}' is an alias template; provide template arguments (e.g. {名}<int>)`（class 与 alias 两形态） | 否 |
| 2 | 模板位实参不是模板 | `template argument {位} for '{模板名}' ('{形参名}') must be a class template, but '{实参}' is not a template` | 否 |
| 3 | 模板位实参是**模板特化类型**（`Box<int>`）而非模板名 | `template argument {位} for '{模板名}' ('{形参名}') must be {}, but '{实参}' is not a template` | 否 |
| 4 | 模板模板实参的签名与形参表不逐位一致 | `template template argument has different template parameters than its corresponding template template parameter ('{形参名}'): {原因}` | 否 |
| 5 | 模板位实参的形态与形参要求不符 | `template argument {位} for '{模板名}' ('{形参名}') must be {类型形参}, but '{实参}' is a value` / `template argument {位} for '{模板名}' ('{形参名}') must be {非类型形参}, but '{实参}' is a type`（两种形态） | 否 |
| 6 | 成员函数模板带 `virtual`（[temp.mem]/2） | `'virtual' cannot be specified on member function templates`（解析期，`[Parse Error]`） | 否 |
| 7 | 成员模板的形参位是模板模板参数 | `template template parameters in member templates are not implemented`（解析期） | 否 |
| 8 | 嵌套的模板模板参数（depth > 1） | `nested template template parameters are not implemented (depth > 1)`（解析期） | 否 |
| 9 | 别名模板递归展开 | `recursive alias template instantiation '{名}' —— 别名模板的底层类型里又用到了它自己，展开会无限递归` | 否 |

★ 第 3 条修的是一个**连"算错"这个症状都没有**的静默接受：`Wrap<Box<int>, int>` 里 `<int>`
静默蒸发，产物与 `Wrap<Box<int>, int>` 逐字节相同——守卫补 `!arg.type->templateArgs.empty()`
后响亮报错。
★ 第 6 条的文案与 clang++-18 **逐字相同**。

## §4 Out of Scope（本模块不做的事）

- **成员类模板 / 成员别名模板 / 静态数据成员模板 一律响亮拒收**：本项目**只做成员函数模板**（learn/34 §3.5）。
- **成员函数模板不得 `virtual`**：不是"暂不支持"，是当场报错（[temp.mem]/2 是强制义务）。
- **模板模板形参的形参包（`class...`）不做**——签名逐位比对时没有"包"这一形态。
- **模板模板形参位的默认实参不做**。
- **嵌套 depth > 1 的模板模板参数直接报错**，不做"收下再报错"。
- **别名模板的偏特化不做**（learn/27 §5 边界表登记）。
- **CTAD 只在直接初始化触发**：拷贝初始化 `MyPtr m = 7;` **不触发** CTAD（clang 也不触发）。
- **推导指引只认直接形态**：不做变参指引 `Box(T...) -> Box<T>;`，也不做 `auto` 形态的指引。
