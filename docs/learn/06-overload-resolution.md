# 06 重载决议（S6）

> 子阶段 S6：同名候选（普通函数 + 函数模板们）→ 可行性过滤 → 排序选赢家。

## §0 定位与能力清单

同一个名字背后可能有好几个候选：普通函数、函数模板、它们彼此的重载……
编译器必须**挑一个**出来。这个"挑"标准上分三步：**收集候选 → 判可行 → 排序取最优**。
本文讲 minicc 实现的最小可用子集，并重点标注其中最容易搞错的一步——**偏序**
（两个模板谁更特化）。偏序一旦判反，选出来的就是另一个函数，
而编译期**一路绿灯**。

| 能力 | 一句话 | 状态 |
|---|---|---|
| [over.match.best] 候选收集 | 普通函数与同名函数模板合成同一个候选集 | 已实现 |
| [over.match.best]/2 非模板优先 | 普通函数可行 ⇒ 直接胜出，不进入模板推导 | 已实现 |
| 模板可行性 = 推导成功 | 推导失败（S2~S4 任一原因）即否决该候选 | 已实现 |
| [temp.func.order] 偏序（deduction-based） | 用更特化者自己的参数类型当合成实参，去推导更泛化者 | 已实现 |
| [temp.class.order] 偏序的完整裁决 | 合成类型前缀 + dominance 循环 + 歧义报错 | 已实现（learn/21） |
| 隐式转换可行性 | 实参类型到形参类型的转换序列可行 | 部分（B26/B27 收口：精确 → 可隐式转换 → 无可行候选则报错） |
| [over.match.best] 转换等级排序 | Exact / Promotion / Conversion 三级排序 | 未做 |

| 成员调用的重载择优 | `obj.f(x)` 在继承体系里挑方法 | 已实现（B12/B22/B24/B25 收口后） |

## ① 理论背景

**标准依据**：[over.match.best]（最佳可行函数）、[temp.func.order]（偏序）。

完整重载决议三步：**候选收集 → 可行性 → 排序**。本项目实现最小可用子集：

1. **非模板优先**：普通函数可行（参数个数匹配）⇒ 直接胜出，
   不进入模板推导。这是 [over.match.best]/2 的首要规则。
2. **模板可行性 = 推导成功**：推导失败（S2~S4 任一原因）即否决该候选。
3. **偏序（最易错点）**：F1 比 F2 更特化 ⟺ 用 **F1 自己的参数类型当合成实参**
   去推导 **F2** 成功。方向记忆法：*"更特化者的领域能被更泛化者吸收"*——
   `po(T*)` 的领域（指针）代入 `po(T)` 推导成功（T := T*），
   故 `po(T)` 覆盖 `po(T*)` ⇒ `po(T*)` 更特化 ⇒ 选它。

   本项目省略了标准中的转换排序（Exact/Promotion/Conversion 三级）与
   tie-break 规则；隐式转换仅在非模板可行性处按"个数匹配"粗判。

## ② 设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 候选视图 | 普通函数（m_functionMap）+ 模板候选集（m_functionTemplateCandidates）分开查 | 保持符号表"名字→单符号"的教学模型（S1 决策延续） |
| 偏序实现 | 复用 `TemplateDeducer`，合成实参 = 对方参数类型 | deduction-based partial ordering 本就是标准算法，零新机制 |
| 无偏序关系时 | 保留先声明者（不报 ambiguous） | 简化；日志如实标注"无特化关系" |

## ③ clang 对照

| 本实现 | clang | 简化 |
|---|---|---|
| 非模板优先分支 | `SemaOverload.cpp → AddOverloadCandidate` vs `AddTemplateOverloadCandidate` 的排序权重 | 无转换等级细排 |
| `isAtLeastAsSpecialized` | `SemaOverload.cpp → IsAtLeastAsSpecialized`（调 `DeduceTemplateArguments` 的 partial-ordering 重载） | 无函数参数转换的"去引用/去顶层 cv"标准化 |
| 可行性 = 推导成功 | 推导成功后还要检查隐式转换序列可行 | 本项目只查个数 |

## ⑤ 过程图

```
调用 twice(2)                        调用 po(nullptr)
    ▼                                    ▼
候选: 普通 twice(int)  可行(个数✓)   候选: po(T) 推导 T:=void*  ✓
    ⇒ 非模板优先，结束               候选: po(T*) 推导 T:=void ✓
                                         ▼
                                   偏序: 合成实参 [T*] 推导 po(T) → 成功
                                         ⇒ po(T*) 更特化 ⇒ 实例化 po(void*)
```

## ⑥ 真实版多做了什么、为什么

★ 素材来源：本文 §③ 对照的「简化」列 + `docs/BUGS.md` B21/B22/B24/B25/B26/B27
+ CLAUDE.md「未做」清单（"转换等级排序 [overload.icp]"）。**未查证的写「（本项目未查证）」**。

| clang 真实版多做的 | 为什么可以砍 |
|---|---|
| `SemaOverload.cpp` 的**转换等级排序**（Exact / Promotion / Conversion，以及 [over.ics.rank] 的整套比较） | 本项目只判"能不能转"，不判"转得更好不好"——排序缺失的后果是**两个都可行时选错**，但教学场景里同名同参型的重载极少；真要补，判据单点在 [overload.icp]（CLAUDE.md 已把它列进"未做"清单） |
| `IsAtLeastAsSpecialized` 的**参数标准化**（去引用 / 去顶层 cv 后再比较） | 本项目的偏序直接拿形参类型当合成实参；标准化没做 ⇒ 某些 `T&` / `const T` 组合的偏序会判不出来。完整偏序在 learn/21 补齐 |
| 完整的三级 tie-break（模板 vs 非模板、限定符、成员 vs 非成员、限定名 vs 非限定名） | 本项目只实现了第一条（非模板优先）；其余在教学场景里极少同时触发 |
| **歧义诊断**（两个候选同样好 ⇒ 报 ambiguous 并列出候选） | 本项目在没有偏序关系时**保留先声明者**并如实打日志——这是**有意的教学简化**，代价是"选错"不会响亮报错 |
| 可行性判定里的**实参转换序列**完整检查（clang 的 `CheckArguments`） | 本项目只查参数**个数**；类型层面的可行性后来在 B26/B27 批次补上（`argsBindTo` / `checkArgBinding` 与"可行性"分开，clang 同款分层） |
| ADL 作为**兜底**之外的一等公民并入同一候选集 | 本项目已做（learn/26）：ADL 不是兜底而是**补进同一候选集**——先到先得会静默调错函数 |
