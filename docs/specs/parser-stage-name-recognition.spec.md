# SPEC：parser 阶段名字识别（对齐 clang ClassifyName 骨架）

> 场景类型：**合成判定型**（多分类位判定 + 作用域匹配，无长流程、无写入风险）。
> 对应需求原文：「parser 阶段实现类似 clang 的语义识别」。
> 关联：docs/learn/46（B31 登记表现状）、docs/learn/45（TokenCheckpoint 机制）、
> docs/BUGS.md B35（语句层前瞻重写）、ROADMAP 主线 I。
> 状态：**已签字**（2026-10-23，三项拍板见文末拍板记录）。

## 1. 概念

### 1.1 实体：名字登记表（name registry）

一句话：解析期只读的名字种类账本。

```jsonc
// 实体：名字登记表   落点：独立小模块（include/name_registry.h + src/name_registry.cpp），
// Parser 与 Sema 各持 const 访问（拍板 2，2026-10-23；构造期一次性建立，解析全程只读）
{
  "name": "B",               // 书写形（裸名；嵌套名按作用域字段归属，不入 name）
  "scope": "N",              // 声明所在命名空间；空值语义："" = 全局作用域
  "bits": ["template"],      // 分类位并集（1.2 穷举）；可多选（int S; struct S; 合法并存）
  "source": "token-scan"     // 收集来源：token 流前向扫描 / "builtin" 种子（declval）
}
// 谁写：构造期前向扫描一次写入，之后零写入。
// 谁读：Parser 消费点（模板闸 / 语句层声明判定）、Sema 限定名裁决。
// 查询未命中 = 整个条目不存在（不是存在但 bits 为空）——消费点按「非类型」处置。
```

**在哪些场景起作用**：场景「parser 名字识别」充当唯一判定依据（本项目第一个
也是当前唯一一个解析期语义识别机制，B31 起步、本 spec 升级）。

实体-场景矩阵见 `docs/constraints/01-实体与场景.md` §2。

### 1.2 分类位枚举（穷举，四位）

| 位 | 置位条件（声明形状） | 现有消费点 | 新增消费点 |
|---|---|---|---|
| type | `class/struct/enum X`、`typedef ... X`、`using X =`、`using X = T`（别名）、`namespace A = B` | 无 | **语句层裸名声明判定** |
| namespace | `namespace X {` | 无（骨架对齐） | 暂无 |
| template | `template<...> class/struct/using`、`template<...> 返回类型 名字(`、推导指引、成员模板、模板模板形参 | 表达式主部闸（`id<...>(`/`id<...>::`）、语句层模板 id 链闸 | 无 |
| value | （本 spec **恒不置位**，占位对齐 clang ClassifyName 骨架——拍板 1，2026-10-23） | 无 | 无 |

★ 判定签名规则：任何消费点**只允许依赖单个位的命中与否**，禁止用「不在表里」
做正向判定（不在表 = 未知 = 按宁宽勿窄处置，见异常1）。

### 1.3 名词（本篇专用）

- **登记表**：上面那个账本。构造时前向扫一遍 token 流建立，之后只读。
- **分类位**：一个名字可以身兼多类（`int S; struct S;` 合法），所以是**位并集**
  不是单选枚举。
- **只读投影**：登记表的性质——它是将来 Sema 符号表的**名字种类投影**，
  不是符号表本身：只有「名字是哪类」这一个 bit 的信息，没有类型实体/偏移/重载集。
- **试探回退**：TokenCheckpoint 罩住一次试解析，判据拿到即整体回卷（含日志）。
- **幽灵行**：试探日志没被回卷、混进正式输出的行——B32 批次从基线里清出 14 行。
- **基线**：154 份集成日志+汇编的逐字节契约（`./logdiff.sh`）。

## 2. 正常流程

**整体一张图**（判定型，分支全在图上）：

```text
语句/表达式位置遇到一个名字
        │
        ▼
   查登记表（只读，零日志）
        │
   ┌────┴───────────────────────────────────────────┐
   查不到（条目不存在）                               查到了
   └────┬───────────────────────────────────────────┘
        │                                            │
   全位按 false 处置（宁宽勿窄）                       ▼
   语句层 → 不判声明，走表达式解释                 按消费点取对应位
   表达式层 → 不做模板试探                         │
   （防 a < b > (c) 被误收成模板调用）      ┌──────┼──────────────┬────────────────┐
        │                              type 位   template 位     template id 链    Sema 限定名
        │                              命中且     命中且后跟      任一层不在表      N::B 按作用域链
        │                              语句收尾    `<`/`::`        ⇒ 推翻声明解释   精确匹配
        │                                  │          │                │              │
        │                                  ▼          ▼                ▼              ▼
        │                            声明解释    进模板实参表      回退表达式解释   配不上 ⇒ 响亮报错
        │                           （EmptyStmt） 试探（B31 现状）   （B35 现状）   「no template named
        │                              │                                          'B' in namespace 'N'」
        ▼                              ▼                                          （不再误绑全局 B）
   Sema 照常报错兜底                  完成
   （文案对齐 clang）
```

**步骤**（自然语言，一步一个动作）：

1. **收集**（Parser 构造期，一次性）：前向扫描全部 token，按 1.2 表的声明形状
   把名字写入登记表；`declval` 走 builtin 种子（不经 token 流）。
   【为什么】前向而非边解析边登记：支撑先使用后声明；与 B31 现状相同。
   登记动作**零日志**（B31 纪律）。
2. **语句层声明判定**（parseStatement，B35 前瞻的扩展）：现有「模板 id 链逐层
   查表」规则不变；新增——类型收尾且无声明符（裸 `S;` 形）时查 type 位：
   命中 ⇒ 声明解释（产出 EmptyStmt，「能当声明就当声明」[stmt.ambig]）；
   未命中 ⇒ 维持现状走表达式解释。
   【为什么】现状对类型名 S 永远走表达式解释，与 clang 的 AST 形状不同；
   当前碰巧都能过（rc=0），但判据不在解析层，后续每个依赖该判定的语法都要
   在 Sema 里补一次特判。判定时必打一行日志（键见 §5）。
3. **表达式层模板闸**（parsePrimaryExpr）：维持 B31 现状（template 位命中才
   进 `<...>` 试探），仅查询接口从 `set<string>` 换成多 bit 表的同一入口。
   【为什么】一个查询入口，判据单点（红线 3）。
4. **Sema 限定名裁决**（resolveType 模板 id 分支）：`N::B<...>` 不再裸尾剥
   「取 `::` 后末段查蓝图表」，改为按登记表作用域链裁决：`N::B` 要求
   存在 scope=N、name=B、template 位命中的条目；配不上 ⇒ 报错
   「no template named 'B' in namespace 'N'」，rc=1。
   【为什么】现状把不存在的 `N::B` 误绑全局 B（探针实测走进
   `限定模板名 'N::B' ⇒ 裸名 'B'` 分支后沿错误路径继续），方向性错；
   clang 探针文案见异常4。
5. **诊断文案对齐**：`semantic_analyzer.cpp` 的 unknown-type-name 错误括注
   「本实现用『跳过 <...> + 回滚』的试探法近似」自 B35 起因过时误导排查，
   改为与现状一致的描述（该改动属有意日志漂移，申报后重刷基线）。

### 2.5 更新对照

本业务不改任何磁盘文件/存储表——「写操作」是**登记表内存结构**与
**AST 解释归属**。两个实例：

**实例 A**：`struct S { int x; }; int main() { S; return 0; }`

```jsonc
// 改前 AST（语句层）
{ "kind": "ExpressionStmt",            // ← 改：声明解释（下）
  "expr": { "kind": "VarExpr", "name": "S" } }
// Sema 把类名当变量查符号表，碰巧放行；codegen 产出无意义读

// 改后 AST
{ "kind": "EmptyStmt" }                // 声明解释：type 位命中 ⇒ [stmt.ambig] 声明优先
// 多打一行 [parse:stmt] 判定日志；rc 不变（clang 同样 rc=0，仅 warning）
```

**实例 B**：`namespace N {}` + 全局 `template<class T> struct B {};` +
`int main() { N::B<int> y; return 0; }`（clang 判非法：N 里没有 B）

```jsonc
// 改前 Sema 轨迹
"[resolve] 限定模板名 'N::B' ⇒ 裸名 'B'（蓝图按书写名登记，B35）"
// → 误绑全局蓝图 B，实例化 B_int，沿错误路径继续（方向性错）

// 改后 Sema 轨迹
"[Semantic Error] no template named 'B' in namespace 'N'"   // rc=1，文案对齐 clang 探针
// 全局 B 不再被误绑；真存在 N::B 的用例（tests/lang/test_basics_22 的 N::B<Box> y）
// 走作用域链命中，行为与改前一致（该用例零漂移是验收项）
```

实例 A 与实例 B 之外的既有 154 份基线：**逐字节零漂移**（验收红线）。

## 3. 异常处理

| # | 异常 | 如何处理 |
|---|---|---|
| 异常1 | 名字查不到（条目不存在） | 全位按 false 处置，**禁止**反向推断「它不是类型」。语句层不做声明解释、表达式层不做模板试探；Sema 照常报错兜底（rc=1，文案对齐 clang）。不可重试（编译错误，修源码重编） |
| 异常2 | 同名跨类（`int S; struct S;`） | 分类位并集都置上；裸 `S;` **只看 type 位** ⇒ 声明解释，不读对象（[stmt.ambig] 声明优先，与 clang 一致）。不是错 |
| 异常3 | 登记表误收（前向扫描误把使用点当声明点） | 消费点判据不因此直接放行：模板类消费点仍过 TokenCheckpoint 试探回退，判不出 ⇒ 响亮拒收（rc=1），不静默。误收只损失试探成本，不损失正确性 |
| 异常4 | `N::B` 真不存在、全局存在同名模板 B | 改前：裸尾剥误绑全局 B（方向性错）。改后：作用域链配不上 ⇒ 报错「no template named 'B' in namespace 'N'」，rc=1。不做 did-you-mean 建议（§4） |
| 异常5 | 既有用例的 Sema 轨迹变化 | 只允许实例 B 形态的变化（误绑→报错）；`N::B` 真存在的用例必须零漂移。任何其他漂移 = 实现错了，打回 |

**可重试性**：编译器业务无运行时重试概念——上表异常全部「不可重试（修源码重编）」；
异常2、异常3 不是错。

## 4. Out of Scope（AI 禁止自行扩展）

1. 不做 Parser 持 Sema 活句柄 / 解析期活符号表（用户已拍板否决，理由见
   设计文档否决记录）。
2. 不做值名（变量/函数/形参）收集——value 分类位恒不置位、不参与任何判定，
   仅作骨架占位（是否连占位都省，见待拍板 1）。
3. 不做变量遮蔽模板名的精确裁决（clang 靠活符号表；minicc 保留宽方向：
   登记即视为可见，遮蔽场景响亮拒收）。
4. 不做 `using Base::f;` 名字拉入（B21 遗留边界，另案）。
5. 不做 did-you-mean / Fix-it 诊断建议。
6. 不做 multi-declarator `int a = 1, b = 2;`（探针时发现的相邻缺口，另案登记）。
7. 不做函数风格转型 `S()` / `S(x)` 的类型判定消费点（本机制铺路，消费点另批）。
