## 0. 结论（先给答案）

**能改，但不该全量重写。** 项目注释**已大体符合四段式的骨架**（锚点 / 动机 / demo 三件都在），
真正违规的是 **4 类、合计约 30 处**，逐条列得清、可逐条验收。
全量重写 8046 行注释反而有**信息丢失风险**——现存注释里承载着 BUGS 编号索引、
与 clang 逐字对齐的诊断文案、判据表、以及踩坑后的"反直觉观测"，这些是资产。

标准四段式与硬约束（摘要）：

| 段 | 内容 | 行数预算 |
|---|---|---|
| ① 定位 | 一句话说清"这是什么、干什么" | 1~2 行 |
| ② 源码锚点 | 对应上游实现的确切位置 | 2~4 行 |
| ③ 动机 | **为什么必须这样设计**（不是复述代码） | 2~5 行 |
| ④ demo + 多方样例 | 终态多组样例 + 交叉印证视角 | 6~15 行 |

整块 ≤ 25 行（复杂算法 30 / 多步协议 40，**放宽须说明理由**）；结构性文件头豁免；
硬约束 7.1「锚点必须自己 grep 一遍」、7.2「图必须可验证」。

## 2. 四个缺口

### G1 私人笔记 13 处 `// mrd`（禁止清单第 7 项）

已逐处核对：**每处上方都已有正式注释块**，信息基本重复 ⇒ 多数可直接删。
唯一带独有信息的是 `src/parse/parser.cpp:754` 的「这里并没有实际 advance」（只窥探不前进）。
（ROADMAP 主线 I 第 4 项早已登记，与上一批 69 处 `// wangyang` 同款处置。）

### G2 超预算块 23 块

- **12 块是文件头**（标准 §6「结构性文件头沿用原格式，不受四段式约束」⇒ 豁免）
- 1 块是二次文件横幅（`semantic_analyzer.cpp:31-57`「读法：一条源码走完本文件的数据流」）⇒ 按文件头处理
- **★ 真正超预算 10 块**，最长 53 行

| 文件:行 | 行数 | 病灶 |
|---|---|---|
| `src/parse/parser.cpp:165-217` | 53 | 两块被合并；含 15 行「位置⇒分支⇒建出什么」分派表＝**复述代码** |
| `src/sema/semantic_analyzer.cpp:4850-4889` | 40 | 实例化 S5 三段并列，缺 ③ 动机 |
| `src/parse/parser.cpp:545-584` | 40 | 映射表是合法 ④ demo，但**缺 ③ 动机** |
| `src/ast/type.h:354-389` | 36 | 待查 |
| `src/sema/semantic_analyzer.cpp:298-331` | 34 | decltype 求值 + findMemberType 两块挤在一起 |
| `src/sema/semantic_analyzer.cpp:3186-3216` | 31 | auto 推导 |
| `src/sema/semantic_analyzer.cpp:4219-4248` | 30 | 重载决议三阶段（**正好卡在"复杂算法可到 30"的天花板**，须写明放宽理由） |
| `src/parse/parser.cpp:1768-1796` | 29 | 成员模板 |
| `src/sema/semantic_analyzer.cpp:1904-1932` | 29 | 类声明处理 |
| `src/sema/semantic_analyzer.cpp:1836-1862` | 27 | 符号名单点判据（B20） |

### G3 锚点精度与可验证性

- 96 条锚点里只有 20 次带具体文件路径，其余只写函数名。
- **已确证 1 条真错**：`src/sema/semantic_analyzer.cpp:2819` 的 `ASTContext::getBuiltinType`
  —— clang **没有这个 API**（真身是 `ASTContext::IntTy` / `getIntTypeForBitwidth`，
  `ASTContext.h:947` / `:2382`）。这正是 7.1 要防的那类"照抄别人过期信息"。
- 其余 15 条查不到的原因**各不相同**（语料裁剪 / 上游改名 / 真错），需逐条分类。

### G4 复述式内容

「算法 1/2/3/4 + a/b/c」型分派表（`parser.cpp:165-217` 最典型）—— 读者扫一眼函数体同样能懂。

## 3. 整改批次

### 批次 A —— 私人笔记出源码（13 处）

- 删 12 处 `// mrd`（周边已有正式注释，信息重复）
- `parser.cpp:754` 的「只窥探不 advance」提炼进上方正式注释的 ③ 动机
- 13 条笔记的独有内容按先例提炼进 `docs/NOTES-阅读笔记.md`
- **验收**：`grep -rn "// mrd" src include` 为空；NOTES 新增小节

### 批次 B —— 超预算块瘦身（10 块 → ≤25 行）

- 手法：把**纯机制内容**（分派表 / 穷举 / 逐步推演）搬进对应 `docs/learn/NN`，
  源码只留 3~4 行指针（§6 特例「不重复上层已讲透的内容」是硬要求）
- 搬进 learn 的内容**写成结论而非推演**（learn 文档本身不受 25 行约束）
- 每块保留：① 定位 1~2 行 / ② 锚点 2~4 行 / ③ 动机 2~5 行 / ④ demo+多方样例 6~15 行
- `semantic_analyzer.cpp:4219-4248`（30 行，重载决议三阶段）按"复杂算法"放宽到 30，
  **放宽理由写进本文件与 docs/learn/50**（§6：放宽必须说明理由，不能默默超）
- **验收**：脚本统计体内超预算块 = 0

### 批次 C —— 锚点补全与自检（96 条）

- **格式统一为 `clang/lib/Xxx/Xxx.cpp:Symbol::method`，不写行号**
  ——理由：oracle 是 clang-18 而语料是 2026-07 上游，行号必漂；7.1 的实质是
  "锚点可 grep 且未过期"，`文件:符号` 才是可长期 grep 的形式
- 逐条在本地语料 grep，分三类落表：
  - ✓ 语料可验证（80 条）—— 补上文件路径
  - ⚠ 语料裁剪 / 上游改名（逐条写明"为什么查不到"）—— 保留原写法并注明
  - ✗ 真错（已确证 1 条：`ASTContext::getBuiltinType`）—— 改成真身
- 产出锚点自检表进 `docs/learn/50`

### 批次 D —— 把标准变成机器断言（`check-comment-style.sh`）

仿 `logdiff.sh` 的护栏思路，把"注释标准"从一次性人工检查变成**可重复执行的脚本**：

1. 体内注释块 > 25 行 ⇒ 报错（文件头豁免）
2. `// mrd` 等私人笔记标记 ⇒ 报错
3. 锚点格式统计（带文件路径的比例）

放在仓库根目录，与 `build.sh` / `logdiff.sh` 同级。
**突变验证**：故意放宽任一判据 ⇒ 脚本必须变红。

## 5. 红线（本批必须守）

- **日志即契约**：注释改动不得触碰任何日志文本 ⇒ logdiff 必须零漂移
- **判据单点**：本批只动注释，不动判据；`check-comment-style.sh` 的判据写单点
- **宁宽勿窄**：脚本对"锚点缺文件路径"只统计不报错，只对两类硬违规报错
- **不动既有结论**：只增不改 `docs/BUGS.md` / `docs/learn/*`（除 learn/50 新增）
- **逐字对齐不动**：诊断文案一律不碰

## 6. Out of Scope（明确不做）

- ❌ 全量重写 8046 行注释（信息丢失风险 > 收益）
- ❌ 删改承载 BUGS 编号 / clang 逐字对齐结论 / 判据表 / 反直觉观测的注释内容
- ❌ 给锚点补行号（版本必漂）
- ❌ 引入第三方注释检查工具（与项目"零外部依赖"取向不合）

- **扫描范围显式列出** `src/` + `include/`（而非"排除若干目录"）——
  第一版用 denylist，当场把 `.cache/googletest-src` 里的 gmock 注释一起判红。

★ **突变验证抓到守卫脚本自身的 bug**：`limit = MAX_BLOCK_ALGO` 是直接赋值，
把 `MAX_BLOCK` 调大来放松判据①时又被按回 30 ⇒ 放松无效 ⇒ 改为 `max(MAX_BLOCK_ALGO, MAX_BLOCK)`。
（"判据写错方向"不是恒真，而是**恒被旁路**——只有做突变验证才看得见。）

## 9. 观测点

本批**只动注释、不动行为**，因此**不新增、不修改任何运行期日志键**——
观测方式只有一种：**逐字节比对**。

| 观测点 | 手段 / 键名 | 必打时机 |
|---|---|---|
| 行为不变（硬验收） | `./logdiff.sh diff` —— 集成日志 + 汇编逐字节比对 | 每批收尾 |
| 注释合规（守卫） | `./check-comment-style.sh` —— 判据①块长 ≤25（复杂算法 ≤30，须含"放宽"说明）②私人笔记黑名单 ③锚点路径比例（**只统计不判失败**）④裸锚点（块内无 `⚠` 豁免登记即报错） | 每批收尾 |
| 判据承重 | `./verify-comment-mutations.sh` —— **8/8**（引入违规必须红、放松判据必须绿，两次实测） | 每次改判据之后 |
| 编译面 | `./build.sh` —— **0 警告** | 每批收尾 |

★ 被审到的注释里**引用的**既有日志键（只在注释文本中出现，改注释不影响它们）：
`[spec:select]` / `[parse:type]` / `[instantiate:class]` / `[sema:targ]` /
`[parse:targ]` / `[subst:map]`。这正是 [lex.comment]/1 那条保证的落点——
**注释对语义零影响 ⇒ 可观测输出必须逐字节不变**，由 logdiff 逐字节把关。
