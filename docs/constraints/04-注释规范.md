# 04-注释规范（唯一权威；来源 mini-restore 三层注释 + minicc 既有惯例）

> 注释是这个项目的**第二输出**——定位是教学仪器，读代码 = 学原理。
> 规范判据：一段注释要么回答「为什么这样设计」，要么给出「对照坐标」
> （clang 文件：函数 / 标准章节 / learn 文档），要么提供「可运行 demo」。
> 三者都不是的注释是噪音，不写。
> 铁律不变：注释改动**绝不许改变任何日志行**（日志即契约，logdiff 把关）。

## 一、三层注释（每个编译单元、公开类型、非平凡函数）

### 第 1 层：文件头 —— Why + Context + 坐标

```cpp
// =============================================================================
// <文件名> —— <一句话职责>
// =============================================================================
// 管线位置：预处理器 → Lexer → ★Parser★ → Sema → …（对照 clang lib/<域>/）
// 核心理论：<标准章节，如 [stmt.ambig] [temp.deduct]>；详见 docs/learn/NN
// 输入 → 输出：<一句话数据形态>
// 关键决策：<最多 3 条，带【为什么】>
// =============================================================================
```

五要素缺一补一：职责 / 管线位置 / clang 对照 / 输入输出 / 关键决策。
已有合格文件头不重写（linker.cpp 式「五步流水线」头即合格变体）。

### 第 2 层：类型 —— What + 对照 + 关键区别

```cpp
// ── <一句话 What> ─────────────────────────────────────────────
// 对照 clang：<文件>:<符号>（或「clang 无对应，本项目特有」）
// 关键区别：<真实版多做 X；本版省掉，因为 Y>——【简化】标签展开
struct NameClassification { ... };
```

规则：公开类型（头文件里的 struct/class/enum）必有对照行；私有实现
类型（cpp 内 file-static）可省对照、保留 What。

### 第 3 层：函数 —— How + 真实版多做啥 + demo

```cpp
// ─── <小节名> ─────────────────────────────────────────────────
// 文法：<EBNF 或 一句话>
// 对应 clang：<文件>:<函数>
// 入参 demo：<具体 token/AST 序列 → 产出>（一个能照着手跑的例）
ExprPtr Parser::parsePrimaryExpr() { ... }
```

规则：非平凡函数（分节 // ─── 标题 ─── 之下的每个函数）必带
「对应 clang」与「入参 demo」两行之一；平凡 getter/单行转发函数免。

## 二、教学标签（强制六种，行内 / 块注释均可）

| 标签 | 用途 | minicc 实例 |
|---|---|---|
| 【概念】 | 设计模式 / 原理 | 访问者 vs 标签分派的判据（learn/29） |
| 【陷阱】 | 容易踩的坑 | 「拿给人看的字符串当机器用的键，早晚出事」（learn/35） |
| 【对照】 | clang 源码坐标 | 对照 clang SemaDecl.cpp:912 |
| 【简化】 | 为什么可以砍 | 无通用 Scope 类，用帧链代替（parser.h） |
| 【历史】 | 演进原因（BUGS 编号） | B35：语句层前瞻重写的原因 |
| 【为什么】 | 决策理由（本项目原有，保留） | 别名分支必须排在类模板分支前 |

每段复杂逻辑至少一个标签；标签后的句子必须**具体**（有事故场景或
标准章节），禁止「为了提高效率」式空话。

## 三、minicc 既有惯例（继续有效，规范不收编只确认）

1. **【为什么】块**：关键决策用 1~3 行「怎么做 → 为什么 → 好处」展开。
2. **demo 行**：解析函数带「入参 demo：Token 流 [a][<][b] → …」。
3. **分节横幅**：`// ─── 节名 ───` / `// ── 小节 ──`，节内函数聚在一起。
4. **中文日志的注释镜像**：日志键（[parse:stmt] 等）在注释里引用时
   原样书写，方便 grep 双向跳转。
5. **零日志纪律**：构造期收集 / 查询路径不打点（name_registry、
   parseIntLiteral 的约定不破，learn/39  rationale 原地保留）。
6. **事故注释带编号**：BUGS.md B 编号写进【历史】标签，可追溯。

## 四、反例（打回情形）

- 注释复述代码：`// i 加一` 配 `i++` —— 无信息量。
- 无坐标的对照：`// 和 clang 类似` —— 没有文件：函数 = 没写。
- 标签空话：`【陷阱】要注意边界情况` —— 哪个边界、什么症状？
- 改代码不改注释：注释与代码矛盾比没有注释更糟（评审必查）。
- 为凑三层而注水：平凡函数硬写 demo —— 规范服务的可读性，不是 KPI。

## 五、执行方式

- 新代码逐条执行；存量代码按批次整合（头文件 → src 分域文件头），
  每批三绿（build 0 警告 / ctest 全绿 / logdiff 零差异）。
- 注释是行为无关改动：任何批次的 logdiff 必须零差异，出现差异 =
  手滑改了代码，当场打回。
