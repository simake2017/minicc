# 01-实体定义法与实体-场景矩阵（minicc 版）

> 编译器项目的"业务对象" = 管线各阶段产生/消费的语言名字与判定数据结构。
> 视角是**语言语义**（这个名字是什么、在哪一层当真），不是物理存储
> （某个 map、某张表）。存储只是实体的落点。
> 本文档是业务全景：新需求进来先在矩阵里找位置；每个场景的权威细节
> 在对应 docs/learn/NN 与 docs/specs/。

## 1. 实体清单（一句话 + 落点 + 生命周期）

| 实体 | 一句话（20 字内，无存储名词） | 落点 | 生命周期 |
|---|---|---|---|
| Token 流 | 源码切成的带种类记号牌 | Lexer 产出，Parser 消费 | 单次编译 |
| 翻译单元 AST | 整份源码的树形骨架 | Parser 产出，Sema 走查 | 单次编译 |
| 名字登记表 | 解析期只读的名字种类账本 | NameRegistry（Parser/Sema 共享 const） | 写一次读全程 |
| 符号表 | 值/函数/类型的决议记录 | SemanticAnalyzer::m_symbolTable | Sema 三趟 |
| 类布局 | 字段偏移/vtable/RTTI 的决议 | ClassLayout（Sema 计算，CodeGen 消费） | Sema 后只读 |
| 模板蓝图 | 模板声明的未替换形态 | TemplateDecl（Parser 产出） | 全程，实例化时读 |
| 推导绑定 | 形参名到实参的类型/值绑定 | TemplateArg（tagged，deduce 产出） | 一次推导 |
| 实例缓存键 | 实例身份的无损编码 | losslessArgumentsKey | 全程 |
| SFINAE 信号 | 软失败的异常载体 | SubstitutionFailure（sfinae.cpp） | 一次候选评估 |
| 编译期常量表 | const/constexpr 整型的值表 | m_constValues + constResolver 回调 | Sema 后只读 |
| ministl 容器 | 自研标准库对象 | ministl/ 双栖头文件 | 宿主/minicc 双栖 |

## 4. 落点对应规则

1. **一个实体一个主结构**，主键 = 语言名字的书写形（不是自增 id）。
2. 字段语义写在**实体定义处**（spec/learn），落点结构只是它的投影；改结构先改定义。
3. 同名不同义必须拆位（名字登记表的 type/template 位并集——`int S;
   struct S;` 合法并存）。
4. 分类/状态字段必须配**穷举表**，散落的 is_xxx 布尔是分类腐烂的开始。

## 5. 实体的粒度判据

- 一个实体 = 编译器作者嘴里**一个名词**（"这个名字""这张登记表""这个蓝图"）
- 拿不准 → 按"它有没有自己的生命周期和写入时机"判：有 = 实体；
  没有 = 别的东西的属性
